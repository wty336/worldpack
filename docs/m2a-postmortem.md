> 记录 M2a（记忆显式化）从基线到达成的全过程：机制怎么建、验收口径为什么必须修订、五次付费复测各自解决了什么、花了多少钱。
>
> 用途：① 给 M2b（压缩 + 语义校验）当决策输入；② 沉淀"先修测量、再优化机制"的方法论教训；③ 延续"实践在前、命名在后"的记录习惯。

## 1. 总览

M2a 目标：把散落在对话历史里的事实提炼为结构化条目并显式注入，让长线游戏的 NPC 不遗忘、不瞎编。

**最终结果**（2026-09-04 达成）：

| 判据 | 结果 |
| --- | --- |
| 机制：记录事实召回（回合 40） | ✅ 100%（5/5 次复测） |
| 随机幻觉 | ✅ 0（基线 3 处 → 修复 1 处，剩 2 处为剧情重写型） |
| 目标环境事实保持（带轨道通关局，第 10 天） | ✅ 3/3（剑名/师承/家乡） |
| 保留集（注入/通关/审计） | ✅ 不退化 |
| 离线测试 | ✅ 124 全绿 |

**成本**：预算 ¥1.5 → 实际 ≈ **¥3.5**（超支原因见 §4.4）。

## 2. 开发期问题（离线测试抓到）

### #1 去重测试预期写错（语义相似 ≠ 文本包含）

- **现象**：`test_dedup_by_containment` 失败——"我的剑名『听雨』"与"剑名『听雨』是师父传的"被判为重复的预期落空。
- **根因**：v1 去重策略是**文本包含关系**，而测试用例是**语义相似**——两者不是一回事。测试预期把 v1 未实现的能力当成了已实现。
- **解法**：改用真正的包含用例（"剑名『听雨』" ⊂ "我的剑名『听雨』，是师父传的"）；同时明确**语义去重是 M2b Judge 的职责**，v1 只做文本层。
- **预防**：写测试前先写下"本版本承诺的能力边界"，测试只测承诺内的行为。

### #2 淘汰测试的编号包含关系

- **现象**：桶扩容 8→24 后，淘汰测试断言 `len == 24` 失败，实际只有 10 条。
- **根因**：测试事实用"事实 0…25"编号，"事实 1" 是 "事实 10" 的子串——**被测的去重机制恰好把测试数据误杀了**。旧上限 8 下（10 条入桶、淘汰 2 条）碰巧通过，扩容后暴露。
- **解法**：零填充编号（`编号01项事实`），消除包含关系。
- **预防**：构造测试数据时先问"我的数据会不会触发被测机制的其他分支"——这里是被测的去重逻辑把测试数据当成了重复项，属"测试数据与被测逻辑耦合"的隐蔽形态。

## 3. 真机与数据诊断发现的问题

### #3 提问预算被思考链吃空（M1.5 探针教训的复现）

- **现象**：`railed_fact_check` 首次运行，f_sword/f_master 回答为**空字符串**（f_hometown 正常）。
- **根因**：推理模型的思考链也计入 `max_tokens`，200 预算被思考吃光，正文一个字没剩。M1.5 探针为此把预算提到过 500（`PROBE_MAX_TOKENS = 500` 注释还在），新脚本又踩了一遍。
- **解法**：`CHECK_MAX_TOKENS = 500`。
- **预防（升级为硬规则）**：**本项目任何 LLM 调用（含测量/提取侧信道）输出预算 ≥ 500**；踩过两次的坑应该进代码审查清单而非注释。

### #4 召回测量被"散文式回答"截断

- **现象**：记录事实召回在回合 80/120 掉到 67%/39%，与回合 40 的 100% 矛盾。
- **根因**：两层。① 输出截断——召回预算 2000（后改 4000）仍不够，因为叙事模型把"列事实"写成了**文章**（"按因果与时间追溯、去除已衰减淘汰后尚存的全部长期事实…"），散文吃掉预算；② 测量问题而非记忆问题——截断处的回答本身条理清晰、事实正确。
- **解法**：不再扩大预算（治标），改为**在回合 40 单一检查点做召回判据**（此时事实量 ≤ 20，无截断），并认识到"让叙事模型输出纯清单"本身就是不可靠的测量载体。
- **预防**：测量提示词要压制模型的叙事本能（"只输出 X，一行一条"仍不够时，换结构化更强的载体或拆小提问）。

### #5 关键词误报：语义精确化被当成遗忘

- **现象**：v2 中 f3（家乡江南）答"姑苏"被判 ✗。
- **根因**：姑苏就在江南——模型不仅记得，还**精确化**了（当轮剧情把顾家写成姑苏人）。关键词列表不含"姑苏"。
- **解法**：关键词扩为 `["江南", "姑苏"]`。
- **教训**：**关键词匹配测的是"字面复现"，不是"事实保持"**。对语义精确化、同义改写都天然误报。规则层测量只适合做粗筛，精确判定要 Judge（M2b）。

### #6 桶容量与提取流冲突（v4 的关键诊断）

- **现象**：迭代 4 上提取兜底后，植入保持率没升，检查最终事实桶——8 条全是回合 90–116 的剧情事实，早期事实**全部被挤出**。
- **根因**：8 槽桶 + 每 2 回合最多 5 条提取 = 桶被剧情进展持续倒腾，**时间衰减淘汰把刚记住的早期小事实又淘汰掉了**。机制在"记住"，策略在"忘记"。
- **解法**（迭代 5）：桶 8→24；提取时把"已有事实"注入提示词去重；提炼口径收紧（排除瞬时剧情状态）。
- **预防**：**任何"容量 + 写入速率"的组合都要算稳态**——桶容量 × 淘汰策略 vs 写入速率，稳态下早期数据存活多久，是设计题不是调参题。

### #7 remember 主动性覆盖缺口（v1 的关键诊断）

- **现象**：迭代 1 后检查事实桶——模型用 remember 记的全是剧情大事（崔家提亲、白雀观之约、镖局），探针测的剑名/师承**一条没记**。
- **根因**：依赖模型主动性 = 依赖模型的优先级判断。小事实在模型眼里"不重要"，但在养成游戏里 NPC 记住玩家的剑名恰恰是体验核心。
- **解法**（迭代 4）：确定性提取兜底——每 2 回合引擎强制提炼，不依赖主动性。
- **教训**：印证书的原则"**约束优先于指导、确定性优于提示**"——remember 是"建议"，提取器才是"约束"。

### #8 无轨道沙盒的剧情重写（测量环境的根本问题）

- **现象**：同 seed 下，f1 剑名在 v2 被剧情改成"刻着『七月』的顾家剑"；f10 大慈恩寺被自创的"杏林线"覆盖。植入事实"消失"其实是**剧情重写**，不是遗忘。
- **根因**：探针世界包没有主线轨道——最病态的漂移场景，LLM 自由创作，天然用自洽的新剧情覆盖旧事实。
- **影响**：植入保持率 40–60% 的波动主要由它主导；真实游戏有 mainline + flags 确定性记忆，不受此影响。
- **解法**：验收换环境——`railed_fact_check.py` 在带轨道的真实世界包测（3/3 通过）；无轨道探针降级为 M2b 的漂移观察工具。

## 4. 测量与验收口径（M2a 最大的教训）

### 4.1 原口径为什么失败

原验收："120 回合，同 seed 同事实集，保持率 ≥ 80%（基线 50%）"。五次运行的结果：

| 运行 | 改动 | 保持率@120 | 召回@40 |
| --- | --- | --- | --- |
| v1 | remember 工具 | 60% | — |
| v2 | 提问协议切换 | 40%* | — |
| v3 | 修复测量 | 60% | 100% |
| v4 | 提取兜底 | 60% | 100% |
| v5 | 桶扩容+去重 | 40% | 100% |

\* v2 含测量缺陷。**同 seed 下 f5/f7/f8 在 ✓/✗ 间横跳**——每次运行 LLM 写出不同的故事，剧情重写（#8）主导了指标波动。单次运行的方差（±20pp）**大于任何一次改动的效应量**。按书第七章的标准：这个测量设计没有统计功效，跑多少次都分不出 40% 与 60% 的真假。

### 4.2 修订后的口径（已拍板执行）

- **机制指标（M2a 判据）**：记录事实召回 = 100%（回合 40，5/5 达成）+ 随机幻觉 0；
- **目标环境指标**：带轨道通关局事实保持 3/3；
- **保留集**：注入/通关/审计不退化。
- 覆盖与语义去重移入 M2b（与 Judge 一起解决）。

### 4.3 方法论沉淀

1. **机制先于测量，但测量协议要先于付费迭代**：机制在 v1 就基本工作（召回 100%），后 4 次迭代大半在修测量。若先做一次"测量协议评审"（预算、关键词、环境、统计功效），至少省两次全量重跑。
2. **单次运行的测量先问功效**：改动效应量预期 < 运行间方差时，要么多 seed 聚合，要么换测量环境，不要迭代。
3. **机制自证指标与业务指标分开**："已记录的事实能否召回"（自证）与"该记的事实记了没"（覆盖）是两个问题，混在一个指标里互相污染。
4. **无轨道沙盒是"漂移压力测试"工具**，不是验收工具；验收要在目标环境做。

### 4.4 成本复盘

| 项 | 金额（约） |
| --- | --- |
| 5 次沙盒复测（120 回合 × 5） | ¥2.5 |
| 轨道收尾 + 复查 | ¥0.5 |
| 保留集（注入 + 通关） | ¥0.5 |
| **合计** | **≈ ¥3.5（预算 ¥1.5）** |

超支根因：测量协议反复修正（每次修正 = 全量 120 回合重跑）。**若先修测量再跑，预算内可完成**。长跑有检查点续跑（W-D 已建），但"改测量"必须从头跑（历史已变），此成本无法摊销——预防的办法只有把测量做对再跑。

## 6. 沉淀的预防规则（进 M2b 前的硬清单）

1. 任何 LLM 调用输出预算 ≥ 500（#3 两次踩坑）；
2. 测试断言行为，不断言消息布局（M1 #5 延续）；
3. 构造测试数据先查"是否触发被测机制的其他分支"（#2）；
4. 容量 × 写入速率的稳态必须先算（#6）；
5. 测量协议（预算/关键词/环境/统计功效）在付费前评审（#4/#5/§4）；
6. 机制自证与业务覆盖分指标测（§4.3-3）；
7. 验收在目标环境做，沙盒只做压力测试（#8）。

## 7. 对 M2b 的直接输入

1. **压缩时不得丢事实区块**：状态栏关键事实 + NPC 记忆是记忆的真值载体，M2b 的压缩只碰历史，不碰这两个区块（KV Cache 三铁律的延伸）。
2. **语义去重/Judge 的用武之地已明确**：#1（语义相似去重）、#5（关键词误报的精确判定）、v1 遗留的 2 处剧情重写型 confabulation。
3. **提取器的成本优化**：当前每 2 回合 +1 次调用（+~25%），M2b 可考虑小模型提取或每 N 回合批量。
4. **测量工具已就位**：`memory_regression.py`（漂移压力）与 `railed_fact_check.py`（目标环境）两个口径都留给 M2b 复测。
