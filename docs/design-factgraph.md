# 第 5 件设计：事实图 Judge（confab 缺席证据的代码化判定）

> 上游：`docs/plan-agent-first.md` 第 5 件。训练暂停期的价值反转件：用代码治
> judge 最大的实测缺口——confab「缺席证据」漏 70%（14B 拦 27.5~32% vs flash 82~90%），
> 不训练而补短板。本文档回答三问：**图从哪来、矛盾怎么判、与语料尺子怎么共存**。

---

## 1. Q1：图从哪来——从材料的**同源真值**构建，不解析字符串

`judge_corpus.build_materials` 已证明：材料 = `ContextBuilder.status_text(state)`，
而 state 由用例的**结构化字段**（`facts` / `npc_memories` / scene / day / stats /
affections）+ 世界包（npc 卡 / lore）物化。故事实图直接从**同一个 state + pack** 构建：

| 图内容 | 来源 |
| --- | --- |
| 已确立事实 | `player_facts` + `npc_memories` + `lore` 文本 + NPC 卡（名字/身份） |
| 数字锚点 | 事实中的全部数字（五十两/中秋前的日期/好感/银两…） |
| 稀有锚点 | 「」引用串 + **桶内 df==1** 的 2~4 字 token（听雨/桂花糕这类专名——复用 BM25 的 IDF 机器） |

- 语料用例（E1）与真实局（game）**同一构建路径**：用例侧新增 `build_state(pack, case)`
  （`build_materials` 改为复用它）；真实局直接用 `state`。
- **不含 flags**（引擎真值纪律不变）；goal 是引导不是真值，不入图。

## 2. Q2：矛盾怎么判——两级：LLM 抽断言（claims）→ 代码查缺席（absence）

```
叙事 → ① factcheck 侧信道（temp=0）：抽取"既成事实断言"的**内容要点**（承诺/债务/身份/
         属性/事件，只收含专名或数字的；氛围/寒暄/套话 → 无；去掉引导词虚词）
     → ② 代码 verify：断言的**强锚点**（数字 / 「」串 / 3~4 字窗口，排除停用词）
         任一强锚点在图内 → 通过
         强锚点**全部**不在图内 → 违规：虚构事实（材料中不存在：<断言>）
```

**为什么是 3~4 字窗口（实测收敛）**：2 字窗口太碎——"欠五十两"会切出"欠五"这种
伪锚点，正常叙事满屏误报；3~4 字窗口才是"密码本/五十两/沈清秋"级的内容载体。
"半真半假"断言（中秋把密码本交给白鸮）的中秋只是 2 字重合，密码本/白鸮两个
强锚点缺席 → 仍被拦。

**为什么只查"缺席"不查"矛盾"**：setting 家族 LLM 已拦 82~95%，不是缺口；
confab 的缺口是"材料没有这条 → 属编造"——这是**纯代码能判**的部分
（材料里有没有这个 token，df 查表即可），正是 14B 系统性失效的那条路。

**副作用（免费收益）**：T2（语气冲突）用例的承诺锚点同样缺席 → 代码同样拦下，
14B 在 T2 上 22% 的缺口一并补上；tier 切片会分开报数验证。

**误报防线（关键）**：
1. 抽取器只收"含专名/数字的**既成事实断言**"（承诺/债务/身份/属性），不收场景描写与
   人物对话套话——叙事正常"新增小角色/场景"不会被抽成断言；
2. 停用词表排除（把/给/答应/曾经/第…）——单字 token 不入锚点；
3. 真机误报的**最终裁决 = E1 normal 语料**（每包 40~76 条）：误报率 ≤10% 是硬门。

## 3. Q3：与语料尺子怎么共存——尺子不动，只换仪器

- **347 条语料一字不改**：E1 测的是"系统能不能拦"，不管拦它的是 LLM 还是代码；
- **judge 输出契约不变**：`check()` 仍返回 (ok, verdict)，合并语义 =
  「代码查到违规 → False（确定性）；否则沿用 LLM 三态判定（含 None=未知）」——
  LLM 空响应时，代码层照常工作（**顺带把"未知"也堵上了一部分**）；
- `JudgeSystem.check(narration, materials, state=None, pack=None)`：
  state/pack 缺省 = 图检查关闭 → 旧调用方零改动（向后兼容）；
- confab 家族在 E1 的目标：**三包拦截率升到 ~100%**（机械补齐），normal 误报 ≤10%，
  ooc/setting 不受影响（LLM 层不动）。

## 4. 成本与耦合

- 每次 judge 检查多一次 factcheck 侧信道调用（purpose="factcheck"，temp=0，预算 500）
  ——judge 本身是每 5 回合 + 关键节点，量小；E1 三包全跑约 +¥1；
- 图构建 = 纯内存查表（事实桶 ≤ 几十条），零网络；
- 工厂/语料/训练数据**零改动**（输入契约不变；judge 提示词不变 → prompt_version 不变）。

## 5. 守卫测试清单（离线）

1. 图构建：facts/数字/「」串/df==1 锚点齐全；flags 不入图；
2. 断言解析：容忍编号/噪声行；「无」→ 空；只收含专名/数字的断言（抽取器提示词守卫）；
3. verify：缺席断言 → 违规（含 T2 同款）；锚点在图 → 通过；停用词不算锚点；
4. 部分接地仍拦：断言同时含图内与图外锚点 → 违规（防"半真"漏网）；
5. merge：代码违规 → False；LLM False/None 且无代码违规 → 原样；三态语义不变；
6. state/pack 缺省 → 图检查关闭（向后兼容）；
7. build_state/build_materials 同源一致性（材料 = status_text(该 state)）；
8. 数字锚点：叙事引用材料中数字 → grounded；引用材料外数字 → 违规。
