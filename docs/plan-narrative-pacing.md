# 剧情节奏与连贯性改进计划（玩家试玩反馈）

> 依据：2026-09-25 玩家试玩反馈「**剧情跳脱、不连贯、少了很多内容**」+ 代码与存档取证。
> 诊断结论：**丰富剧情只是其中一半**——引擎侧存在三个制造"跳"的结构性问题
> （节点无节奏约束 / 节点完成即瞬移 / 空窗无内容兜底）和一个制造"不连贯"的长程记忆问题。
> 先修结构，再补内容，否则加了内容剧情照样跳。
> 本文档 = 计划 + 执行复盘（滚动更新）。

---

## 1. 证据与诊断

### 1.1 已修过的不在本计划内

跨天衔接此前已修过一轮（commit 6686c36 / 5806797）：`end_day` 叙事化、【时序推进】过场、
act 衔接指令（先辞别再行动）、Web 故事框追加式日志。**这些只覆盖"跨天"这一种衔接**；
本计划处理的是它们没覆盖的面：节点间衔接、节点节奏、空窗填充、长程记忆。

### 1.2 四个未解决的问题（按严重度）

| # | 问题 | 证据 |
| --- | --- | --- |
| 1 | **节点触发无节奏约束**：只看 flag/day 硬条件，节奏全靠作者手排，排错就"开场连击 + 长真空" | campus_otome 的 N2 触发条件只有 `{flags: {transfer_done: true}}`（`mainline.yaml:35`），无天数门槛；实测 autosave-788bf2796b81.json：**第 1 天第 2 回合，N1、N2 两幕全部完成**（转学第一天刚答应帮人，紧接着"一周后"的社团招新当场开演）；随后 N3 要求 day≥6，是 4 天真空。武侠包则是反面：N2 要求 day≥5，冒烟存档第 2~4 天零剧情事件，主角独自在山上对崖壁说话 |
| 2 | **节点完成 = 瞬移**：完成即把场景重置回 `start_scene`、在场 NPC 清空，节点之间没有任何收束/转场叙事 | `storyline.py:214-217`（end_turn 内）：`state.scene = start_scene; state.present_npcs = []`；`test_storyline.py:93` 有测试固化了这一行为 |
| 3 | **空窗期无内容兜底**：事件少、门槛高（好感 ≥30 新手期不可达）、0.3 概率且 `once`；日常行动多为单人（好感推不动 → 关系剧情休眠） | 武侠包 3 个事件在 7 天冒烟中触发 **0** 次；`events.py` 三类触发（condition/schedule/time）均无"仅日常阶段"门——时间事件甚至能在主线节点中途插进来 |
| 4 | **长局记忆太薄**：压缩近窗仅 6 回合、摘要目标仅 800 字，十几天的局前面剧情被压成梗概，模型接不上玩家记得的细节 | `game.py:95`（`keep_turns: int = 6`）、`compression.py:15`（`SUMMARY_MAX_TARGET = 800`） |
| 5 | **反重复是"事后 + 字符级"检测**：重复的叙事已经播给玩家，提示只影响下一轮；检测靠相邻轮 SequenceMatcher ≥0.6 与 6-gram 覆盖 ≥0.25，**换措辞的桥段重复抓不到**；回看窗口仅 6 轮，窗口外写过什么模型和检测器都看不见 | `game.py:67-70`（阈值/窗口常量）、`game.py:302-342`（先播后检、命中注入提示） |
| 6 | **记忆有存储与注入天花板，承诺不是一等公民**：玩家事实存 24 条 / NPC 记忆 20 条，满额淘汰；注入 = 常驻 3 条 + 检索 top-10，权重 0.4·recency + 0.4·importance + 0.2·relevance——新琐事挤掉旧约定，相关旧事排不进坑位；约定/承诺与琐事平等竞争，**choice_log（关键抉择）append-only 却完全不注入上下文** | `memory.py:33-42`（上限/权重/K 值）、`context.py:210-217`（注入区块无 choice_log）、确定性提取每 2 回合 ≤5 条且依赖叙事显式写出（`game.py:404`） |

### 1.3 判定

- "跳" = 问题 1 + 2（节奏失配 + 空间瞬移）；
- "少了很多内容" = 问题 3（空窗真空）+ 世界包本身节点/事件密度低；
- "不连贯" = 问题 4（长程记忆）+ 问题 2（无衔接叙事）；
- **"反复重复"** = 问题 5（检测层）+ 问题 3/E（素材供给薄，模型只能在窄空间打转）+ 记忆 top-K 固定注入（同一批记忆反复当话头）；
- **"没记住"** = 问题 6（存储/注入天花板 + 承诺非一等公民）+ 问题 4（摘要压薄）。

## 3. 批次 A：节点完成过渡叙事（去瞬移）

### 目标

节点完成的那一刻，剧情有一个"收束回合"而不是瞬间清场；玩家停留的地点与在场人物
保持连续，直到下一个节点的 `on_enter` 或玩家主动移动。

### 设计

1. **取消完成即重置**：`end_turn`（`storyline.py:214-217`）不再把 scene 重置回
   `start_scene`、不再清空 `present_npcs`。场景语义收敛为：**只有三件事能改场景**——
   新节点 `on_enter.scene`、玩家 `change_scene`、日程行动 `scene`。（跨天本就不重置，一致。）
2. **【节点完成】升级为收束回合**：节点完成时注入引擎元消息（name=engine，措辞纪律同
   【时序推进】）：「本节点剧情已达成，请用两三句收束本段：交代余韵、与在场人物的告别或
   约定，为下一段留出自然空间。不要发起新情节。」随后**立刻进行一次有界的收束叙事回合**
   （复用 `_narrate` 事件级联的回合机制，上限 1 次）。
3. **边界与守卫**：
   - 收束回合若同时达成结局（end_turn 同回合判出 ending）→ 跳过收束，结局文本接管；
   - 收束回合计入反重复/审计/usage，与其他回合同纪律；熔断兜底路径不变；
   - 下节点触发（begin_turn）仍注入 on_enter 任务卡，衔接语义不变；
   - `test_storyline.py:93` 的"场景复位"断言改为"场景保持"，补"收束回合发生一次 +
     场景保持 + 在场保持"用例。

### 验收

- 全量 pytest 通过（含改写后的 storyline 用例）；
- 真机冒烟：节点完成回合出现收束叙事，状态栏场景与上回合连续，审计零偏差；
- campus_otome 真机试玩：N1→N2 之间不再出现"同一天凭空换场"。

## 4. 批次 B：节点节奏门槛（opt-in + lint）

### 目标

杜绝"同一天连开两幕"与"无过渡的背靠背节点"，但**不静默改变现有包的行为**。

### 设计

1. **节点新字段 `cooldown_days`（默认 0 = 现行为）**：距上一个节点完成日不足 N 天时，
   `_try_enter_node` 跳过该节点（顺延到条件满足且冷却已过的那天）。语义与 `when` 的
   day 条件正交：`when` 管"最早何时"，`cooldown_days` 管"与上一幕至少隔几天"。
2. **check-worldpack 新增节奏 lint（warning，不 error）**：非首节点 `when` 不含 day 条件
   → 提示"该节点可能在上一节点完成的同日触发，确认是否符合预期（如需间隔请加 day 条件
   或 cooldown_days）"。campus_otome N2 正是此 lint 要抓的形态（briefing 写"一周后"，
   引擎却当天就开）。
3. **不加引擎默认冷却**：改默认值会静默改变 P1/P2（评测留出包）与其他包的判定路径，
   违反"评测尺子不悄悄动"的纪律；用字段 + lint 让作者显式表达节奏。

### 验收

- schema/加载期校验覆盖 `cooldown_days`（负数拒绝、类型校验）；
- 离线用例：cooldown=1 时同日不再连开、次日进入；
- check-worldpack 对 campus_otome 输出节奏 lint（批次 E 修复后归零）。

## 5. 批次 C：空窗插曲（`idle` 触发类型）

### 目标

日常阶段（无进行中节点）不再真空：包作者可声明"只有闲下来才会发生的小际遇"。

### 设计

1. **events 新触发类型 `idle`**：

   ```yaml
   - id: ev_idle_cliff_hint
     title: 崖壁残字
     trigger:
       kind: idle
       when: {day: {gte: 2}}     # 同 time 纪律：只允许 day 条件
       chance: 0.5               # 可选，缺省 1.0
       min_idle_turns: 2         # 可选：自上一事件/节点结束以来的空闲回合下限
     script: |
       收剑歇息时，你注意到崖壁半腰的青苔下似乎还有别的刻痕……
     effects: {stats: {martial: 1}}
     once: true
   ```

2. **引擎语义**：`idle` = time 事件的"仅日常阶段"版——`current_node is None` 时才在
   `end_day` / 回合末检查；主线进行中**绝不触发**（插曲不打断主线）。once/priority/
   效果结算复用现有事件机制。
3. **校验**：check-worldpack 对 `idle` 复用 time 的 when 纪律（只允许 day），规模门禁
   不强制（插曲是加分项不是必需品）。
4. **手册更新**（§3.4 与陷阱表）：何时用 idle、与 condition/time 的选择依据。

### 验收

- 离线用例：主线中不触发 / 日常阶段按 day+chance 触发 / once 防重；
- 冒烟：武侠包加入 1~2 个 idle 插曲后，第 2~4 天空窗出现至少一段插曲叙事。

## 6. 批次 D：章节回执 + 摘要扩容

### 目标

长局里"你记得的剧情"模型也记得：每个节点完结时沉淀一份**章节回执**，成为模型的长程锚点；
摘要与近窗适度扩容。

### 设计

1. **章节回执**：节点完成时（批次 A 的收束回合之后）用 compress 级预算的 LLM 调用生成
   该节点回执——结构：节点名 / 发生了什么 / 达成的约定与承诺 / 遗留线索 / 关键数值变化。
   存入 `state.chapter_notes`（append-only，含 day），save/load、审计同步覆盖。
2. **注入策略**：状态栏新增 `<chapters>` 块——**最近 2 份回执全文 + 更早回执按检索相关性
   选取**（复用 rank_facts 三因子），预算上限防止膨胀；回执同时进事实图（叙事引用不算编造）。
3. **摘要扩容**：`SUMMARY_MAX_TARGET` 800 → 1500；`keep_turns` 6 → 8。**先测量后合入**：
   用 compress 评测集与长局基线对比 token 成本与摘要质量（重点看"约定/数字/名字"保留率），
   成本增幅不可接受则只调其一。
4. **Web 侧（可选加分）**：剧情回顾按章节分组展示（数据源即 chapter_notes），本批次只做
   引擎侧，Web 呈现单独立项。

### 验收

- 离线：回执生成/注入/持久化全链路用例（FakeClient）；注入预算不超限；
- 100 回合 longrun_probe：第 80+ 轮仍能正确引用早期节点的约定（对照现状）；
- 成本记录：每节点回执 + 摘要扩容的实测 token/¥ 增量落 reports。

## 8. 批次 F：长程记忆一等公民 + 重复感知升级

> 源头：2026-09-25 玩家第二轮反馈「**有些对话反复重复，有些内容 AI 又没记住**」。
> 与批次 D 同属长程链路（D 管上下文供给，F 管注入策略与检测），紧随 D 执行。

### 目标

玩家记得的三类东西——**自己做过的关键选择、立过的约定、聊过的近期桥段**——模型同样记得；
重复的桥段在写出来之前就被看见，而不是播出去之后才提示。

### 设计

1. **承诺/约定一等公民**：
   - `remember` 增加 kind（`fact` / `commitment`，缺省 fact）；commitment 恒注入（不参与
     top-K 竞争），兑现后由引擎或模型打 resolved 降级为普通事实；
   - 兜底：确定性提取产出中含"约定/答应/承诺"模式的事实自动升级 commitment。
2. **关键选择注入**：`choice_log` 摘要进状态栏——"你已做出的关键选择"块（最近 3 条
   全文 + 更早条数）。玩家最记得的就是自己的选择，这是主线记忆的地基，成本近乎为零。
3. **注入权重复调（先测量后合入）**：relevance 0.2 → 0.3~0.35 对照实验（relevance 拉高 =
   聊到相关话题时旧事实更容易浮出）；`PLAYER_FACTS_LIMIT` 24 → 48。验收尺：脚本化
   "约定保留率"评测（第 3 天立约 → 第 25 天追问，对照改动前后命中差异）。
4. **NPC 记忆注入去雷同**：top-K 每轮同序 → 模型反复拿同一条记忆当话头。第一步提示词层
   （最小改动）：注入的记忆区块标注「背景记忆仅供衔接，不要向玩家复述」；无效再做注入
   轮换因子（近期已被叙事引用过的记忆降权）。
5. **反重复从事后转事前**：
   - 事前：状态栏注入「近窗桥段清单」——最近 6~8 轮叙事各一句话概括（引擎侧从历史提炼，
     不额外调 LLM），模型动笔前先看见自己写过什么；
   - 事后：`REPETITION_WINDOW` 6 → 与 keep_turns(8) 对齐；评估 6-gram → 5-gram 与
     相邻轮结构相似度（抓"换措辞的同桥段"）；judge_every 语义校验加"与近期桥段重复"
     维度放最后（改 JUDGE_SYSTEM 是纪律上的末位手段）。
6. **认清天花板**：重复的另一半根子是**素材薄**（批次 E）——引擎修到"不再雷同"，
   内容补上"有新可写"，两批合起来才闭环。

### 8.1 NPC 记忆专项（玩家实测确认的重点：「确定了的事 NPC 像忘了一样」）

写入链路取证（2026-09-25）：NPC 记忆的唯一写入口是**叙事模型自觉调用
`remember(target=npc)`**——引擎侧所有确定性剧情结算**都不写 NPC 记忆**：

| 环节 | 现状 | 后果 |
| --- | --- | --- |
| 关键选择 / 事件 / 行动效果结算 | 只写 stats/flags/counters，**不写在场 NPC 的记忆** | 玩家在诗会上夺魁、答应过谁、救过谁——引擎全知道（flag），NPC 的记忆里可能什么都没有 |
| 确定性提取兜底（每 2 回合） | **只写 player_facts，不路由 NPC**（`_extract_facts` 提示词即"玩家长期事实"） | 兜底网对 NPC 完全不生效 |
| 注入 | **NPC 在场才注入**其记忆 top-10/常驻 3 | NPC 不在场 = 模型对"它知道什么"为零；NPC 回场时若记忆没写入或被检索排掉，表现即"忘了" |
| 存储 | 每 NPC 上限 20 条，满额按 importance 升序淘汰（缺省 importance=5） | 中低重要性的旧约定被挤掉 |

**修复（按优先级）**：

1. **共同经历自动入记忆（治单点故障，本批核心）**：关键选择结算、事件触发、行动效果
   结算时，**给在场 NPC 确定性写入一条事件记忆**——素材用现成真值（选择文本/事件
   title/行动 label + 天数），importance 分级（关键选择 8 / 事件 6 / 行动 5），按
   choice/event/action id 去重防重写。语义：**flag 是剧情真值，在场 NPC 目击的
   flag 变化就该进它的记忆**——不靠模型自觉，与"LLM 无 flag 写权限"同方向。
2. **确定性提取路由 NPC**：提取提示词增加"涉及角色"输出位，事实涉及具体 NPC 时
   同时写入该 NPC 记忆（importance 4~5，同一去重/冲突管线）。
3. **离场不失忆**：NPC 记忆中 importance ≥8 的条目（约定/重大事件）在 NPC **不在场**
   时也以一行"离场角色已知"注入状态栏（与 commitment 常驻合并实现，防上下文膨胀）。
4. **存储扩容 + 淘汰保护**：memory_limit 20 → 40；importance ≥8 的记忆豁免淘汰
   （最后淘汰）。先测量 NPC 记忆注入区块的字符增量。
5. **注入口径复核**：NPC 记忆检索 k=10/pinned=3 与玩家事实口径对齐，评估 pinned 3→5
   （重大事件不该靠检索碰运气）。

### 验收

- 离线：commitment 恒注入 / resolved 降级 / choice_log 注入块 / 桥段清单生成的单元用例；
  **NPC 记忆专项**：关键选择后在场 NPC 自动获得事件记忆（按 id 去重）、提取路由 NPC、
  importance ≥8 离场注入、淘汰豁免的单元用例；
- "约定保留率"评测脚本入 `scripts/`，改动前后数据落 `reports/`；NPC 侧加"目击保留率"
  （第 N 天关键选择 → 第 M 天对该 NPC 提及，模型应知道）；
- 真机长局（longrun_probe 100 轮）：第 80+ 轮追问第 3 天的约定能答对；NPC 回场后能
  正确引用此前共同经历；重复提示触发率下降且换措辞重复有检出；
- 注入总预算（状态栏字符数）不超现有动态区上限的 1.2 倍。

## 9. 纪律与门禁（继承工作偏好）

1. **分批 commit**：一批 = 一个 commit，docs 随手同步（worldpack-manual 新字段/新触发类型、
