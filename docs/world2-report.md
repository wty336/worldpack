# 第二个世界包《问道长生》——通用性验证报告

> design.md §16 M3「框架化」的验收项：「世界包规范定稿 + 第二个世界包（玄幻）验证"换包即玩"」。
> 本文档记录：新世界包的设计、与第一个世界包的差异矩阵、验证方法（离线 + 真机）与结论、
> 验证过程中发现的引擎层内容耦合及修复。

---

## 1. 目标

回答一个问题：**引擎（Harness）对故事内容是否零耦合？** 即新作者只写 YAML（不碰一行引擎代码），
换一个完全不同的时代/世界观/数值体系/人物关系，同一个 agent 引擎能否直接开玩。

验证方式：写第二个世界包《问道长生》（仙侠修真），与《江湖旧梦》（唐风武侠）在
**时代、属性 schema、NPC 数量、节点结构、事件类型、结局数量**六个维度全部差异化，
然后跑三级验证（§4）。

## 3. 验证过程中发现的引擎耦合（已修复）

「换包即玩」要求在换包后**用户体验不穿帮**。验证发现 2 处引擎层的内容泄漏：

| # | 位置 | 问题 | 修复 |
| --- | --- | --- | --- |
| G1 | `game_agent/web.py` 页面 | `<title>`/`<h1>` 硬编码「江湖旧梦」——玩新包时 Web 标题显示错误游戏名 | 页面静态文案改为中性「文字养成游戏」；`/api/new` 返回世界包 `name`，前端 JS 动态渲染标题与 `<h1>` |
| G2 | `game_agent/web.py` + `cli.py` | `web` 命令无世界包参数，只能服务默认包 | `web` 新增 `--pack` 参数，经 `GAME_WORLDPACK` 环境变量传入 uvicorn 模块（`_pack_path()`） |

依据：F1 审查修复（`start()` 不得含内容文案）的同一条原则推广到 Web 壳层。
修复后 `tests/test_web.py::test_index_page_served` 断言页面**不含**「江湖旧梦」。

其余引擎层零耦合：`grep` 全库确认无任何对「沈清秋/长安/武功/银两」等内容词的运行时引用
（仅 cli/web 的默认路径常量、scaffold 模板的**示例值**、文档字符串示例——均非逻辑依赖）。

## 5. 真机冒烟结果（2026-09-07，deepseek-v4-flash，seed=7）

`scripts/xianxia_smoke.py --days 8`，生产同款引擎配置（extract_every=2 / compress_threshold=30000 /
judge_every=5 / reflect_every=10），transcript 落盘 `saves/xianxia-smoke.txt`。

| 指标 | 结果 |
| --- | --- |
| 结局 | **「问道长生」达成**（第 8 天魔潮抉择后，条件：relic_taken + crisis_done + 修为≥35） |
| 协议稳定性 | 12 个叙事回合 / 20 次 API 调用（change_stat → submit 循环），**零熔断、零协议错误、零重试提示** |
| 数值真值 | 21 条 stat_log，**零偏差审计通过**（T3） |
| 事件系统 | **time 类**「宗门小比」（day≥5）与 **schedule 类**「灵泉顿悟」（打坐 30%）均真机触发——两类旧包未跑过的路径在新包上工作正常 |
| 记忆系统 | 玩家事实提取正常：『拜入剑峰』『残碑拓纹「剑落星沉」』『魔帅认得剑印纹路』（extract/remember/dedup 侧信道全部无异常） |
| 语义校验 | Judge 2 次调用全部通过，全程零「校验反馈」、零「反重复提示」 |
| OOC/禁用元素 | 机读抽检（手机/微信/AI/机器人/手枪/互联网）**零泄漏**；角色人格稳定（苏晚晴清冷简练、白芷活泼跳脱贯穿全程） |
| 检定三档叙事一致性 | 第 2/5/7 天打坐检定失败 → 叙事写「气机滞涩/心浮气躁」；第 1/4/6 天成功/大成功 → 叙事写「气海初成/酣畅淋漓」——**叙事与代码结算结果一致** |
| 成本 | 约 ¥0.126（空闲时段计价），入 286K / 出 20K token，前缀缓存命中率 94% |

**结论：同一个 agent 引擎在零代码改动下，把全新故事从开场跑到结局——**
关键抉择门、数值契约、检定、事件、记忆、Judge、审计全部在仙侠世界观下正常工作，
且生成的叙事是"仙侠味"的（山门收徒、灵泉吐纳、洗剑池论剑、魔潮夜袭），而非旧包的武侠口吻。
Agent 的通用性（设计目标「换一个世界包 = 换一个游戏」）得到真机验证。

### 6.2 验证发现与修复（引擎侧）

- G1/G2（§3）：Web 壳层的标题硬编码与不可选包——**内容泄漏而非逻辑耦合**，已修复并回归测试；
- 引擎其余部分（对话循环/上下文/数值/剧情状态机/事件/结局/存档/审计/Judge/记忆）**零改动**适配新包。

### 6.3 后续建议

1. **回归语料池化**：把 `scripts/xianxia_smoke.py` 泛化为 `--pack` 参数化的通用通关验收，新包加入 CI（T1~T3 自动化）；
2. **语料对齐**：新包 `judge_corpus.yaml` 为紧凑版 9 条——✅ **已扩充到 30 条**（2026-09-08，6 OOC+6 设定+6 虚构+12 正常），真机门禁 100%/0%，规模门禁已对全包机器化（见 `docs/plan-worldpack-qa.md` §7.5）；
3. **条件事件路径**：新包「洗剑池夜话」（好感≥30 条件触发）在本轮未触发（好感 17）——该路径已由《江湖旧梦》与离线测试覆盖，后续可用「赠丹探访」策略真机复现；
4. **第三个包候选**：都市/科幻背景，进一步验证 `forbidden` 表与文风注入在近现代世界观下的表现——✅ **已落地（2026-09-07）**：《霓虹深处》（world-packs/urban_neon），见 [docs/world3-report.md](world3-report.md)。
