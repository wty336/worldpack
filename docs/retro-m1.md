## 3. 真机联调 Bug 档案（最有价值的部分）

共 **9 个**，按发现阶段分类。核心教训：**离线测试全绿 ≠ 能跑**，真机是另一种测试。

### 3.1 单元测试抓到的（3 个）

| # | 现象 | 根因 | 修复 |
| --- | --- | --- | --- |
| B1 | NPC 好感变更 KeyError | 好感容器以 NPC id 为键，代码却用 "affection" 查 | 键修正 + 审计回放测试 |
| B2 | 节点 briefing 属性不存在 | 写成了 `node.briefing`，实际是 `node.on_enter.briefing` | 属性路径修正 |
| B3 | 违规选项被放行 | 选项过滤的"防滤过头"守卫在过滤后不足 3 个时放回原列表 | 改为"安全兜底优先，宁可选项变少" |

### 3.2 真机才抓到的（6 个）——离线测不到的原因见括号

| # | 现象 | 根因 | 修复 | 离线为何抓不到 |
| --- | --- | --- | --- | --- |
| B4 | 第二回合 API 400 | `submit_narration` 没回配对的 tool 结果，DeepSeek 校验历史时报错 | 回占位结果 + **协议配对不变量测试** | 假客户端不做配对校验 |
| B5 | 抉择后回合连续熔断 | 推理模型思考链吃 `max_tokens` 预算（1024 不够），输出截断无工具调用 | 预算提至 2048 + 失败反馈带 finish_reason | 假客户端无预算概念 |
| B6 | N1/N2 永远无法完成 | `met_shen`/`poetry_top3` 无任何代码路径可写（LLM 无 flag 白名单） | 关键选择补路径 + **引擎新增"completion 可达性"加载期校验** | 推演型内容缺口，测试测不到"永远卡死" |
| B7 | 叙事混入 `<invoke>` 工具调用文本 | 模型把工具调用格式"写"进叙事内容（训练语料残留） | 提示词禁止 + 引擎兜底清洗 `clean_narration` | 假客户端只回合法内容 |
| B8 | 流式首回合崩溃 | openai SDK v3 流式对象不自动聚合，`Stream` 无 `.choices` | 手动累积 delta（content/tool_calls/reasoning） | 离线测试无流式路径 |
| B9 | 基线大量"空答案" | 探针提问 `max_tokens=120` 被思考链吃光 | 提至 500 + 记录调用路径 | 方法缺陷，跑完才暴露 |

### 3.3 防复发机制（B4–B9 的直接产出）

- 协议配对不变量测试（每条 tool_calls 必须被全覆盖配对）；
- completion 可达性加载期校验（内容设计错误 → 报错而非运行时卡死）；
- `clean_narration` 纠正层 + 提示词禁止（双保险）；
- 探针方法固化（预算参数 + mode 记录 + 断点续跑）。

## 4. 诚实负结果（5 项）

| # | 负结果 | 原因 | 转化 |
| --- | --- | --- | --- |
| N1 | 第一局「长相守」失败：好感 35→27，沈清秋闭门不见 | 脚本玩家用复读机式客套话，NPC 连续负反馈——**叙事引擎质量好，驱动策略差** | 分阶段台词驱动（初识/诗会/承诺三段），第二局通关 |
| N2 | 注入检测误报"泄露" | 模型引用玩家原话拒绝（"什么'系统提示词'"）被关键词误判 | 泄露标记改为"玩家不可能说出的引擎专有词" |
| N3 | 第一轮基线数据不可信 | 探针预算缺陷致大量空答（见 B9） | 方法修复后重跑，拿到可信的 50% 保持率 |
| N4 | 存档不含对话历史（用户实测发现） | M1 简化，设计文档的"剧情摘要"留给了 M2 | M1.5 存全量历史；M2b 升级"近窗+摘要" |
| N5 | 节奏过快：第 1 天好感 +12、四段大事件 | 日常对话中模型"加戏"无约束 | M2 候选：好感日上限、大事件归属事件系统 |

## 6. 成本与资源

| 项 | 估算 |
| --- | --- |
| 通关局 | 5 次尝试（wanderer 1 次成功、together 4 次其中 2 次失败/中断）≈ 30 万 token |
| 注入/冒烟/自走 | ≈ 6 万 token |
| 基线 | 2 次 × 120 回合 ≈ 数十万 token/次 |
| **总计** | **约 ¥3–6**（flash 档 + 缓存命中） |

**教训**：全程没有精确记账——API 响应的 `usage` 字段从未采集。M2 起所有脚本统一累计 usage 并写入报告（成本也是评估指标，书第 7 章）。

## 7. 方法论验证（书的原则 ↔ 实证）

| 书中原则 | M1 实证 |
| --- | --- |
| 测试随工作包同步写 | 抓到 B1–B3 + 保护了后续所有重构 |
| 真机联调不可省 | 抓到 B4–B9，离线假客户端模拟不了提供商行为 |
| 约束编码化（C3） | completion 可达性校验把"内容写错"变成"加载报错" |
| 数值代码化 + 真值校验 | 注入攻击天然免疫，真机验证通过（银两/好感纹丝不动） |
| 评估先行 + 边界集 | M1.5 基线数据直接翻转 M2 优先级：记忆显式化 > 压缩 |
| 保持简单 | 1 NPC/2 节点/2 事件的规模已暴露全部真实问题，规模更大只会更难修 |
| 中立轨迹/存档 | 读档无缝、换模型无接口债（B4 修复后即验证） |
| 上下文腐化预警 | 基线 50% 保持率 + 3 处虚假记忆固化，M2a 的靶子 |
