# M1.5 · 体验基线与债务清理 —— 执行计划

> 背景：M1 全部验收达成（95 测试全绿、两结局真机通关、审计/注入/OOC 通过），但存在五个缺口：长会话基线缺失、真人试玩为零、通关脚本不可复现、时间触发事件未实现、M2 范围过肥。
> M1.5 的目标：**在进入 M2 前补齐基线与小债，并把 M2 拆成可独立验收的三段**。
> 原则：边界集 + 保留集（先立基线再改进）、最小 diff + 可回滚、保持简单。

## 1. 工作包明细

### W-A · 可复现性修复

**问题**：`playthrough.py` / `injection_test.py` 用未 seed 的 `random.Random()`，后山奇遇（30% 概率）等日程事件不可复现——违背"边界集+保留集"的可比较原则。

**动作**：
1. 两个脚本加 `--seed` 参数（默认 42），`Game(..., rng=random.Random(seed))`；
2. seed 与事件序列写入存档/报告（`saves/*.json` 的 `run_meta` 字段）；
3. 真机冒烟：同 seed 重跑一小段，确认事件触发序列一致。

**验收**：`--seed 42` 两次运行的事件序列一致（offline 用 stub rng 验证；真机小样本抽查）。

### W-B · 时间触发事件机制

**问题**：design.md §9 三类触发只实现了条件、日程，时间触发（第 N 天必发生）缺失。

**动作**：
1. `EventTrigger.kind` 增加 `"time"`，`when` 只允许 day 条件（worldpack 加载期校验）；
2. `Game.end_day` 中检查并触发时间事件（触发消息注入下一天的首个叙事回合）；
3. 离线测试：时间事件在指定天触发、once 防重、提前不触发、非 day 条件的 time 事件被加载期拒绝。

**验收**：离线测试全绿；不新增世界包内容（现有两条通关路径不受影响）。

### W-C · 自动存档 + 重开引导

**问题**：存档只有手动单槽位；结局后只能读档，没有重开入口。

**动作**：
1. 每个主线节点完成时自动存档到 `saves/autosave.json`（引擎侧钩子，不打扰叙事）；
2. CLI 增加 `/new` 命令（重置 GameState + 清空历史，回到开场）；
3. 结局提示文案改为「/load 读档 · /new 重新开始 · /quit 退出」。

**验收**：离线测试（节点完成 → autosave 存在；/new 后状态为初始值）+ 真人试玩顺手验证。

### W-D · 长会话基线（M2 压缩的边界集）

**问题**：M1 最长 ~40 回合，全量历史塞得下；M2 的 300 轮验收没有任何基线。需要先测"当前引擎跑到多长开始腐化、丢什么"。

**动作**：
1. 建记忆保持回归集：10 条关键事实，分三类——
   - **早期事实**（第 1–5 轮植入）：如"我的剑名叫'听雨'""我与沈姑娘约定暗号'七月'"；
   - **中期事实**（第 30–60 轮植入）：如"我答应帮老樵夫送柴""沈府后门亥时虚掩"；
   - **数值事实**：某次关键选择的结果（如诗会选择登台）。
2. 写 `scripts/baseline_probe.py`：
   - 用固定 seed 跑 120 轮日常对话（与通关脚本同一驱动）；
   - 在 40 / 80 / 120 轮三个检查点，逐条提问模型（"我的剑叫什么？"），由 judge 判定对错；
   - 输出腐化曲线：每档轮数 × 每类事实的保持率，落盘 `saves/baseline-report.json` + Markdown 报告。
3. 成本估算：120 轮 ≈ 100K–150K token ≈ ¥0.3–0.5（flash 档）。

**验收**：报告产出，明确回答三件事——① 第一处事实丢失出现在哪一档；② 哪类事实最先丢（早期/中期/数值）；③ 是否出现重复调用/答非所问等腐化症状。**基线本身无对错，只有数据**；若 120 轮内零丢失，结论就是"M2a 可以延后"，同样是有效结论。

### W-E · 真人试玩（用户）

**动作**：用户玩 1–2 局（`uv run python -m game_agent play`），带着体验清单玩，记录问题。

**体验清单**（供参考，不必逐条）：
1. 节奏：行动/对话/事件的推进节奏是否舒服？等 LLM 响应多久？
2. 选项质量：日常选项是否自然衔接？有没有违和或重复？
3. 剧情连贯：NPC 是否记得之前的事？有没有前后矛盾？
4. 数值反馈：好感/属性变化是否有感知？状态栏信息够不够？
5. 卡壳情况：有没有不知道该干什么、或剧情推不动的时刻？
6. 结局体验：结局到来的时机是否自然？重开是否顺畅？

**产出**：体验问题列表（随意记，格式不限），并进 W-F 的 M2 规划。

### W-F · M2 拆分规划（文档）

**动作**：根据 W-D 基线与 W-E 体验问题，把 M2 拆成三段并落文档（`docs/plan-m2.md`）：

- **M2a（核心）**：剧情摘要压缩 + 记忆回归集复测（压缩后 40/80/120 轮保持率不得低于基线——边界集+保留集）；
- **M2b**：NPC 记忆 + 时间触发事件内容落地 + LLM-Judge 语义层 OOC；
- **M2c（可选）**：Web 前端、多人场景。

**验收**：`docs/plan-m2.md` 成文，每段有独立的完成标准与验收方式。

## 2. 依赖与顺序

```
W-A ──→ W-D（需要可复现 seed）
W-B ──→ W-C（引擎小债，独立并行）
         ↘
W-E（用户，可与 W-D 并行进行）
         ↘
W-F（最后，汇总基线与体验数据）
```

- W-A/B/C 由引擎侧完成，除 W-C 的冒烟外全部离线；
- W-D 需要真机（~¥1），可在 W-E（用户试玩）期间跑；
- W-F 等 W-D 报告 + W-E 反馈齐了再动笔。
