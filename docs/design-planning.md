# 第 4 件设计：规划层 plan-and-execute（节点目标 → 子步骤 + 进度跟踪）

> 上游：`docs/plan-agent-first.md`（agent-first 路线第 4 件）。
> 本文档回答三个问题：**子步骤从哪来、谁维护进度、和卡壳保护的边界在哪**。
> 核心原则一句话：**计划是"引导"，不是"真值"——三个硬机制（completion flag 判定、
> 关键选择接管、卡壳保护）全部不动。**

---

## 1. 要解决的问题

现状：节点进行中，状态栏只有一行"当前主线目标：{goal}"（`context.py` `status_text`）。
模型在节点内即兴发挥，靠 30/60 轮的卡壳保护兜底（`storyline.py` `stuck_threshold=30` →
推进提示、`forced_threshold=60` → 命运事件）。中长节点的绕圈表现为：目标明确但
"不知道先做什么"，来回寒暄不推进。

解法（plan-and-execute）：把 goal 拆成 2~4 个**顺序子步骤**，状态栏常显
"当前步骤 → 下一步"，让模型的每一步落在路线上。

---

## 2. Q1：子步骤从哪来——作者手写优先，LLM 侧信道兜底

| 来源 | 机制 | 取舍 |
| --- | --- | --- |
| **作者手写（优先）** | `mainline.yaml` 节点新增可选 `steps: [str]`（1~4 条，每条 ≤40 字） | 确定性、零成本、可校验（check-worldpack 加长度/数量校验）；作者最懂自己的剧情 |
| **LLM 侧信道生成（兜底）** | 节点进入且无 `steps` 时，一次性调用 `plan_node`（purpose="plan"，temp=0，预算 500）把 goal+briefing+场景拆成子步骤 | 存量世界包零改造成本；每节点只调一次（每次 playthrough 几个节点，成本可忽略）；**失败/空/格式非法 → 静默无计划 = 退化为现状行为** |

- 生成输入**不含 flags**（引擎真值纪律不变）：只给 goal / briefing / on_enter.scene；
- 解析容忍编号/项目符号；1~4 条、非空、≤40 字，超限截断，0 条 = 无计划。

## 3. Q2：谁维护进度——代码按 flag 增量推进（真值驱动，不采信自报）

**机制**：节点进入时给 `state.flags` 拍快照；每回合 `end_turn` 对照快照，
**有任一 flag 值变化 → 计划指针 +1**（上限 len−1），**推进后以当前 flags 重新起算**
（对照基线跟着指针走——否则同一个翻转会每回合重复触发，实测踩坑后修正）。

**为什么这是"真值驱动"**：flag 只能由代码路径写入（关键选择效果 / 事件效果 /
日程行动效果）——flag 翻转 = 剧情**真实**前进了一步。指针是 flag 的投影，不是模型自报，
不违背"服务端真值校验"原则。

**两个设计取舍（明说）**：

1. **一次翻转只推一步**（即使一个关键选择写 2 个 flag）：步骤是"节拍"，不是"计数"，
   一个剧情事件 = 一个节拍；
2. **纯好感/纯数值型进度不推指针**（如"好感 ≥40 即完成"的节点，全程无 flag 翻转）：
   指针停在当前步是**无害的**——计划块仍展示全部步骤与目标，卡壳保护照常兜底。
   （v2 可选：把 stat/affection 增量也计入推进代理，本轮不做，保持代理纯 flag。）

**完成判定不变**：节点完成仍只认 `completion` 条件（代码复核），计划指针与完成判定
完全解耦——指针到头 ≠ 节点完成，模型仍可能被要求补足 flag。

## 4. Q3：与卡壳保护的边界——软引导 vs 硬兜底，各司其职

| 层 | 触发 | 性质 | 动作 |
| --- | --- | --- | --- |
| 计划块（新） | 节点进入即常显 | **软引导** | 状态栏显示 [x]/[→]/[ ] 步骤，防"不知道先做什么" |
| 卡壳保护（旧，不动） | 30 轮 → 提示；60 轮 → 命运事件 | **硬兜底** | 阈值、文案、阶段机**一字不改** |

**边界规则**：

1. **阈值不动**（30/60）：计划是降卡壳率的引导层，不改变升级时机——计划失效时
   （生成失败/步骤写歪），硬兜底保证行为与今天完全一致；
2. **失败静默回退**：无计划 = 现状（状态栏无 `<plan>` 块），一切照旧；
3. **与关键选择不冲突**：`pending_choice` 期间引擎照常锁定输入给固定选项，计划块
   仍显示（对选择简报是补充上下文，无害）；
4. **与命运事件同向**：强推事件会写 flag → 指针自然前进，两机制互相喂料不打架；
5. **与内轮自校正（第 2 件）同向**：自校正的 judge 材料里会带计划块（状态栏同源），
   judge 能看到"这步该干什么"，判"推进力不足"更准。

---

## 5. 数据与状态设计

| 位置 | 字段 | 说明 |
| --- | --- | --- |
| `worldpack.py` `NodeSpec` | `steps: list[str] = []` | 可选字段，作者手写子步骤；check-worldpack 加 1~4 条/≤40 字校验 |
| `state.py` `GameState` | `node_plan: list[str]` | 当前节点生效的计划（作者 steps 或 LLM 生成） |
| | `node_plan_step: int = 0` | 计划指针（0 起，上限 len−1） |
| | `node_flags_snapshot: dict` | 进节点时的 flags 快照（推进判据） |

- **生命周期**：`_try_enter_node` 成功时重置（`node_plan=list(node.steps)`、
  `step=0`、快照=当前 flags）；`end_turn` 完成分支随其他字段一并清空；
- **存档兼容**：`to_dict`/`from_dict` 带缺省回退（老档无此字段 → 空计划），version 不动；
- **生成位置**：`game.py::_ensure_plan(node)`——在 `_narrate` 的 `begin_turn` 返回新节点时
  调用（仅当 `plan_node=True` 且 `node_plan` 为空且 goal 非空）；storyline 只做纯状态
  重置与指针推进，不碰 LLM。

## 6. 上下文注入（`context.py` `status_text`）

节点进行中且 `node_plan` 非空时，在「当前主线目标」行后追加：

```
<plan>
主线步骤（随剧情推进自动勾选）：
[x] 1. 打听诗会消息
[→] 2. 准备参赛作品
[ ] 3. 参加诗会并夺前三
</plan>
```

- **对 judge 材料的影响（关键）**：E1 语料与工厂材料都用 `status_text` 构造，
  但两者都不设 `node_plan` → 材料**零变化** → **E1 与工厂无需重测**（理由写进执行记录）；
- `query_world` 结果同步带上当前步骤（与状态栏同口径）；
- **compress 不动**：计划进度随状态栏快照进入历史，摘要的"未完成目标"条款已覆盖，
  不改 COMPRESS_SYSTEM（不新增 compress 契约面）。

## 7. 配置与接线

- `Game.__init__` 新增 `plan_node: bool = False`（默认关，与 extract_every 等惯例一致）；
- cli.py / web.py 传 `plan_node=True`（生产开；每节点仅一次侧信道调用，成本可忽略）；
- purpose="plan" 暂回退主模型（不扩 Settings 路由面；若以后换本地小模型再补，B3 同法）。

## 8. 守卫测试清单（离线）

1. `NodeSpec.steps` 可选 + check-worldpack 校验（数量 1~4、每条 ≤40 字）；
2. 作者 steps：进节点即生效，无 LLM 调用（假客户端响应耗尽即证）；
3. LLM 生成：`_ensure_plan` 解析输出（容忍编号/项目符号）；空/非法 → 无计划；
4. 指针推进：flag 翻转 +1、一次多 flag 只 +1、上限 len−1、无翻转不动；
5. 快照：进节点时快照当前 flags（含进入前已存在的 flag，不误推进）；
6. 生命周期：节点完成 → 计划字段清空；新节点 → 重置；
7. 存档回环：to_dict/from_dict 保留计划与指针；老档（无字段）加载 = 空计划；
8. 注入：status_text 有 `<plan>` 块且 [x]/[→]/[ ] 位置正确；无计划时无块；
9. query_world 带当前步骤；
10. 卡壳保护回归：30/60 阈值与阶段机行为不变（既有测试即护栏）。

## 9. 验证与待观察

- 离线：全量 pytest（含既有卡壳保护测试不回归）；
- 真机：`worldpack_smoke`（real）跑 ancient_jianghu——turn 契约变了，冒烟是 turn 侧
  唯一端到端门禁（约 ¥0.1~0.3）；E1/工厂免重测（§6 理由）；
- 待观察：长局中卡壳保护 stage 1 触发次数是否下降（`longrun_probe` 或 trace 统计
  `stuck_stage` 消息）；计划质量抽查（生成步骤是否贴合 goal）；每节点计划成本。
