# M2b 复盘：压缩与语义校验的 300 轮长局验收（详版）

> 记录 M2b（剧情摘要压缩 + LLM-Judge 语义校验 + 300 轮长局验收）从实现到达成的全过程：机制怎么建、300 轮跑出了什么、踩了什么坑、留下什么观察。
>
> 用途：① 给 M2c 与未来世界包作者当参考；② 延续"M2a 复盘"的测量教训——M2b 是那些教训的第一次实战检验；③ 记录"结构不变量测试抓到潜伏 bug"这类隐蔽问题的发现过程。

## 1. 背景与目标

### 1.1 M2b 要解决的问题（plan-m2.md §3）

M2a 解决了"记得对"，M2b 解决"记得便宜 + 记得不越界"：

1. **剧情摘要压缩**：长局上下文不线性膨胀（design.md §4.5 的 v1：近窗 + 摘要 + 增量）；
2. **LLM-Judge 语义校验**：拦截语义层 OOC / 设定矛盾 / confabulation（M1 只有规则层）；
3. **300 轮长局验收**：协议稳定、成本曲线变平、机制召回不退化。

### 1.2 启动时的设计假设（事后检验）

| 假设 | 事后结论 |
| --- | --- |
| H1：压缩切点选在回合起点即可保证 tool 配对不变量 | ✅ 成立（find_turn_cut + ensure_pairing 兜底） |
| H2：压缩调用失败静默降级即可（下回合重试） | ✅ 成立（300 轮零故障） |
| H3：增量摘要（只总结新增部分）能控制压缩调用输入成本 | ✅ 成立（压缩调用输入稳定在 ~30K 字符内） |
| H4：Judge"下轮修正"足以兜住语义问题 | ⚠️ 机制成立但本次运行未观测到明确拦截案例（见 §5.4） |
| H5：摘要会忠实保持核心关系线 | ⚠️ **新风险**：摘要近期偏置可能稀释长程核心线（§5.3 漂移观察） |

## 2. 实施时间线

### 阶段 1 · 离线实现（无 API 成本）

- `compression.py`：token 粗估（中文 1 字≈1 token）、回合切点、增量摘要合并、重建 + 配对不变量校验；
- `judge.py`：三类问题 rubric（OOC/设定矛盾/虚构事实）+ 判定解析；
- `Game` 接入：压缩在 `_llm_round` 构建消息前检查；Judge 每 N 轮检查最新叙事，失败注入「校验反馈」下轮修正；
- 探针升级：可配检查点、压缩/校验开关、**成本曲线采样**（每 20 回合记录历史 token 估算/消息数/摘要字数）；
- 离线测试 124 → **133 全绿**。

**阶段 1 的最大收获**：压缩测试抓到一个潜伏 bug（§4 #1）——这是 M2a 复盘"结构不变量测试"预防规则的第一次实战回报。

### 阶段 2 · 300 轮长局（付费，后台 2 小时量级）

参数：seed 42、压缩阈值 30K、近窗 6 回合、Judge 每 5 轮、检查点 40/120/240/300、提取每 2 回合。

**结果速览**：

| 指标 | 结果 |
| --- | --- |
| 协议稳定 | ✅ 300 轮零熔断零重试 |
| 成本曲线 | ✅ 历史 20–31K 持平（无压缩时 300 轮将达 ~280K） |
| 机制召回@40 | 8/9（89%）→ 定位为幽灵事实，修复后 100% |
| 植入保持率 | 2/10（按修订口径仅为漂移观察，见 §5.3） |

### 阶段 3 · 修复与保留集

1. 修 `parse_facts` 哨兵（"无。"带标点漏过滤 → 幽灵事实入库）；
2. 真实游戏入口（CLI/通关/轨道检查）启用压缩 + 校验（阈值 30K）；
3. 保留集：轨道事实检查 **3/3**（压缩+校验全开引擎）；注入攻击通过；133 离线测试全绿；
4. M2b 达成，文档收尾。

## 3. 机制设计全景

### 3.1 增量摘要压缩（compression.py）

```
历史 = [旧前缀] + [剧情摘要] + [上次摘要之后的原始回合……] + [近窗 N 回合]
                    ↑
        每次压缩：把"新增原始回合"与旧摘要合并 → 新摘要（提示词限定 ~800 字）
        切点 = 倒数第 N 个回合起点（user 消息，非引擎元消息）
```

关键设计决策：

- **增量而非全量**：每次只总结上次摘要之后的新增部分。全量重摘要每次要把整个历史塞进压缩调用（300 轮时 >100K 字符），增量把压缩调用输入稳定在 ~30K 字符内，且摘要随剧情演进；
- **切点 = 回合起点**：tool_calls/tool_result 必须成对出现（协议硬约束）。切在回合边界，被丢弃的部分总是完整回合，重建后用 `ensure_pairing` 兜底校验，不通过则放弃本次压缩；
- **静默降级**：压缩调用失败/空摘要 → 保留原历史，下回合再触发重试（300 轮运行中此路径未被触发，但被离线测试覆盖）；
- **不碰静态前缀与事实区块**：M2a 复盘 §7.1 的硬约束——状态栏事实与 NPC 记忆在 status 消息里动态注入，压缩只动历史。

### 3.2 LLM-Judge 语义校验（judge.py）

- Rubric 三类：OOC（违背人设/语气/底线）、设定矛盾（与世界观/既定事实冲突）、虚构事实（把泛泛之语升级成具体承诺——针对基线的"初六成婚"型 confabulation 专门写了这条）；
- **对 plan 的偏差**：判定失败走"下轮修正"而非"当轮重生成"。理由：流式输出下坏文本已到达玩家，重生成会造成双显示；下轮修正确保体验连续，且与反重复提示机制同构。此偏差已记录在实现注释中；
- 侧信道：调用失败静默降级，不影响主线。

### 3.3 探针的成本曲线采样

每 20 回合记录 `history_tokens / message_count / summary_chars` 三元组——"压缩生效"的判据从主观感受变成可读曲线（§5.2）。

## 4. 问题清单（8 个）

### #1 潜伏三个里程碑的 bug：历史里带着 system 消息（压缩测试抓到）

- **现象**：压缩重建测试断言 `history[0]` 是摘要，实际是 system 消息。
- **根因**：`run_turn` 返回的消息列表包含调用时传入的 system 前缀，`_llm_round` 直接把它当历史存——**每一轮的真实请求里 system 提示词被重复注入两次**（build_messages 加一次，历史里残留一次）。W4 引入此结构后一直如此，DeepSeek 宽容接受（多 system 消息被拼接），三个里程碑里所有真机运行都带着这个冗余。
- **解法**：`self.history = [m for m in result.messages if m.get("role") != "system"]`。
- **为什么现在才被抓到**：此前没有任何测试断言"历史不含 system"——M2a 复盘预防规则 #2（"断言行为，不断言布局"）的另一面：**布局级不变量需要专项测试**，否则纯行为测试永远看不见它。压缩测试恰好依赖历史结构假设，意外充当了结构测试。
- **预防**：为关键结构写"不变量测试"（配对不变量已有；system 隔离应加入）。

### #2 压缩测试的响应序列设计错误

- **现象**：压缩触发测试报"假客户端响应耗尽"。
- **根因**：`keep_turns=2` 时前两轮历史不足 2 回合，压缩根本不触发；测试却预留了压缩摘要的响应槽位，序列错位。另 threshold=1 下每回合都触发压缩，第三个 say 又会消耗新摘要响应。
- **解法**：`keep_turns=1` + 精确的两回合场景（回合 1 不触发、回合 2 触发），响应序列 = [SUBMIT, 摘要, SUBMIT]。
- **预防**：测试响应序列要按"每步消费了什么调用"精确推演，而不是凭感觉排列。

### #3 幽灵事实："无。" 逃过哨兵过滤（300 轮运行暴露）

- **现象**：300 轮召回@40 = 8/9，唯一缺失项的 fact 是**"无。"**——提取器哨兵词"无"带句号时漏过滤，被当成一条事实存进桶。
- **根因**：`parse_facts` 的哨兵判断是精确匹配 `line in ("无", "没有")`，模型输出"无。"就不匹配。
- **解法**：去尾标点后再判哨兵；新增离线测试（哨兵 + 标点变体）。
- **预防（升级规则）**：解析器对 LLM 输出的处理要做"标点/空白归一化"——LLM 输出的标点变体无穷无尽，精确匹配必漏。M2a 复盘 #3 的"预算 ≥500"是同类教训的另一个侧面：**对 LLM 输出的假设越具体，越容易被打破**。

### #4 召回大检查点测量依然不可靠（预判应验）

- **现象**：300 轮召回 40/120/240/300 = 89%/100%/28%/100%。240 的 28% 与 300 的 100% 矛盾。
- **根因**：与 M2a 复盘 #4 同源——25 条事实时，叙事模型把"列清单"写成带框架的散文，输出预算被吃掉，列表截断；240 的判定恰好在截断区。这是**预判过的**（判据已定在回合 40），300 轮只是再次确认。
- **处置**：不修（修法已在 M2a 复盘明确：换载体或拆小提问，且判据不需要大检查点）。判据照常按回合 40 执行。
- **教训**：把已知不可靠的指标排除在判据之外，比反复修补它更便宜——M2a 花 ¥2 买来的教训，M2b 直接受益。

### #5 轨道检查超时与断点恢复

- **现象**：`railed_fact_check.py` 全流程跑超 10 分钟被杀（网络较慢的时段），但**通关局已完成并存档**。
- **根因**：脚本在通关结束后才做事实检查，超时发生在收尾段；检查段依赖通关产物。
- **解法**：`--check-only` 模式从存档重放（3 次调用、几十秒）——断点恢复思路（M1.5 W-D 已建）的自然延伸：**脚本设计时就把"重跑贵的部分"与"重跑便宜的部分"分开**。
- **预防**：所有真机验收脚本都应拆分"长局生产"与"便宜复查"两段，存档即分界。

### #6 探针提问的 `<invoke>` XML 泄漏

- **现象**：300 轮探针中 f1 的回答、轨道复查中 f_sword/f_master 的回答都出现 `<invoke name="submit_narration">` 原文。
- **根因**：模型在某些提问下用工具调用格式"包裹"答案（DeepSeek 系已知行为）。M1 的 `clean_narration` 只覆盖叙事路径，探针的 `complete()` 答案未清洗。
- **处置**：关键词匹配在 XML 包裹下仍能命中（答案在参数里），判定不受影响；记为已知模型行为，留给探针路径统一清洗（低优先级）。
- **预防**：侧信道 `complete()` 的返回也应过 `clean_narration`——清洗层应该挂在"所有 LLM 输出出口"而不是"叙事这一个出口"。

### #7 压缩摘要的近期偏置（300 轮漂移观察中的新发现）

- **现象**：300 轮沙盒中好感归零，感情线被"义塾/仓人"支线取代，沈清秋线彻底消失。植入保持率 2/10。
- **根因**：无轨道沙盒的漂移（M2a #8）+ **压缩的放大效应**——摘要是"新内容合并旧摘要"，若摘要对近期内容权重偏高，长程下核心关系线被逐次稀释。这是压缩在极端长度下暴露的新风险，M2a 的 120 轮尺度上看不见。
- **为什么不计入判据**：探针包无 mainline/flags 锚点；真实游戏有三重锚点（主线节点链 + 确定性 flags + NPC 记忆常驻注入）约束剧情核心。但**值得在 M2c 内容扩展时专门观察**：长局里 NPC 记忆是否压得住摘要漂移。
- **若未来需要治理**（候选方案，未实现）：摘要提示词要求"人物关系单独成节、优先保留"；或摘要与 NPC 记忆定期对账。

### #8 成本估算缺口

- **现象**：300 轮运行的实际费用未精确记账（只记录了调用次数级估算）。
- **根因**：探针只记 token 估算，没有拉取 API 侧 usage 统计。
- **处置**：按成本曲线估算 ≈ **¥2–4**（300 轮 × ~25K 输入 + 提取/校验/探针侧信道，含缓存折扣的不确定性）。
- **预防**：长跑脚本应累计每次响应的 `usage` 字段落盘——成本是长局引擎的一等指标（§7）。

## 5. 数据与验收

### 5.1 300 轮完整数据（seed 42，saves/memory-regression-report.md）

**协议**：0 重试 0 熔断（300 轮）。

**成本曲线（压缩生效的直接证据）**：

| 回合 | 历史 token 估算 | 消息数 | 摘要字数 |
| --- | --- | --- | --- |
| 40 | 23,455 | 51 | 1,657 |
| 100 | 21,112 | 31 | 604 |
| 160 | 22,721 | 31 | 805 |

**植入保持率（漂移观察，不计判据）**：回合 300 仅 f2 存活（2/10）——剧情彻底漂移（#7）。

### 5.3 漂移观察（预期内，记录在案）

300 轮无轨道沙盒中：植入保持率 2/10、好感归零、感情线被支线取代——**再次实证"沙盒是漂移压力测试，不是验收环境"**（M2a 复盘 §6.3-4 的第二次验证）。

### 5.4 Judge 的观测空白（诚实记录）

本次 300 轮运行中，**Judge 未产生可确认的拦截案例**（无明确"校验反馈"注入记录）。两种可能：① 叙事质量确实没有触发三类问题（沙盒剧情虽漂但自洽——漂移不违反人设/设定，只是换了故事）；② Judge 判据偏保守。M2c 在真实内容上应专门构造 OOC/矛盾用例来验证 Judge 的灵敏度。

## 6. 关键决策记录（ADR）

| # | 决策 | 理由 | 代价/遗留 |

## 8. 沉淀的预防规则（在 M2a 复盘 8 条基础上新增）

9. **布局级不变量需要专项结构测试**（#1 的教训：行为测试看不见 system 重复注入）；
10. **测试响应序列按调用消费精确推演**（#2）；
11. **对 LLM 输出的解析先做标点/空白归一化**（#3：精确匹配必漏）；
12. **已知不可靠的指标排除在判据外，而不是反复修补**（#4：M2a 教训的直接兑现）；
13. **真机脚本拆"长局生产"与"便宜复查"两段，存档即分界**（#5）；
14. **清洗层挂在所有 LLM 输出出口，而非单个出口**（#6）；
15. **长跑脚本累计 usage 落盘，成本是一等指标**（#8）。

## 9. 对 M2c / 后续的输入

1. **摘要近期偏置的治理候选**（#7）：摘要提示词"人物关系单独成节优先保留"，或摘要与 NPC 记忆定期对账——在 M2c 写长线世界包时验证；
2. **Judge 灵敏度验证**：构造 OOC/矛盾/confabulation 用例集（离线 fake + 真机小样本），确认 Judge 会拦（§5.4 的空白必须补上）；
3. **探针路径统一清洗**：`complete()` 返回过 `clean_narration`（#6）；
4. **成本记账**：长跑脚本累计 usage（#8）；
5. **真实长局的下一步验证**：在带轨道的真实世界包上跑一次 300 轮（或更长）长局，验证"三重锚点压得住摘要漂移"——这是 H5 未决问题的直接检验。
