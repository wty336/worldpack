## 1. 决策表：训什么、训多少

| 模块 | 实测缺口（2026-09-11/12 重测后） | 进训练集 | 训练量 | 评测集目标 | 优先级 |
| --- | --- | --- | --- | --- | --- |
| **extract** | railed 轨道事实 **0/3**（flash 3/3）；根因 = 事实提取层未入桶 | ✅ | **600~1500** | 每包 30~50 条期望事实 | **P0 必训** |
| **judge** | **confab（缺席证据）同难口径仅拦 27.5~32% → 漏 ~70%（2026-09-12 §3.5.6c）**；ooc 100%、setting 82~95%；误报 0% 已达标 | ✅ | **500~1200**（**confab 家族 ≥40%**，见 §4.2.2） | 每包每类 ≥20（对抗 ≥60、正常 ≥40）；**confab 必须卡中性** | **P0 必训**（由"P0 小补强"升级） |
| **compress** | 保全率 0.23~0.67 vs flash 0.47~0.89（长输入最弱 0.27） | ✅ | **200~500** | 20~30 样本（规则保全） | P1 要训 |
| **reflect** | 14B 仅 1/3 产出合法洞察（2/3 诚实输出「无」——**合法输出，非失败**） | ⏸ **第一批不训**（程序化档零成本照造，排最后可砍） | 200~400（第二批） | 30+ 样本 | P2 最低 |
| **dedup** | **双方 10/10 = 100%（无缺口）** | ❌ **只造评测集** | 0 | 100~200 对（含易混淆） | 回归护栏 |

**为什么 dedup 不训**：单 LoRA 多任务下，dedup 是全任务中最简单的一个（输入 <1K、输出 2 字），
梯度信噪比最低，参与训练会稀释其他任务的容量并可能把模型往"极短输出"方向带；
而它作为护栏的价值（防回退）远大于作为训练样本。

**为什么 judge 从"小补强"升级为"必训"**（2026-09-12 §3.5.6c 判决性实验）：
把两侧语料改成同难（卡中性）后实测，**confab 家族在旧三包拦 32%、在新包拦 27.5%**
—— 即"材料中没有该承诺 → 属编造"这条**缺席证据路线**被系统性漏掉 ~70%，
而同类题 flash 能拦 82~90%（不是坏题、不是窄化、与题材无关）。
判官其余两族已近满格（ooc 100%、setting 82~95%），**全部差距集中在 confab 一家** →
judge 训练量的分配必须向该家族倾斜（≥40%），否则平均分会被 ooc/setting 盖住。

### 3.3 冻结纪律

1. 评测集**先提交进 git 并打 tag**（如 `phase1-eval-frozen`），训练开始后不得再改；
2. 训练数据与评测集做**指纹去重**：同一包、同一回合前缀、同一 fact 不得跨集（前缀级去重，非样本级）；
3. 训练报告必须记录 `eval_set_sha256`；评测报告必须记录 `budget_policy` + `prompt_version`；
4. 评测集**不得**包含任何训练数据的生成种子（合成器 seed 与评测器 seed 隔离）。

## 3.5 Step 1.5 · 世界包覆盖：零样本跨包对照 → 世界包工厂（2026-09-12 新增）

> **编号说明**：本节插在 Step 1 与 Step 2 之间，用 `3.5` 以免打乱既有 § 引用。
>
> **动机**（用户提问，2026-09-12）：现有评测集与训练数据都围绕 `江湖旧梦` / `问道长生` /
> `霓虹深处` 三个包展开——而本项目的卖点（`scripts/import_story.py`：**任何小说导入即可玩**）
> 决定了**新包是常态而非例外**。只在这三包上训练与评测，测出来的可能是"记忆"而不是"能力"。
> 本节把"防窄化"从设计意图落成**可执行步骤**：先量化风险，再决定投入。

### 3.5.1 先分清"包"影响哪一层

| 层 | 与包的关系 | 现状 |
| --- | --- | --- |
| 输入/输出契约（`status_text` 槽位、事实行式、判词格式、摘要格式） | **无关** | 已是包无关：新包只是往同一批槽位填新字符串 |
| **能力（变换）** | 弱相关 | 模型学的是"散文→结构化事实""材料+叙事→判定""长历史→摘要"；包提供**词汇与结构习惯** |
| **评测尺子** | **必须无关** | 评测包不得出现在训练数据，否则测的是记忆 |

### 3.5.2 真问题是"轴值太窄"，不只是"包太少"

现有三包**题材不同、结构同质**：中文 / 第三人称 / 节点 4~6 / NPC 1~2 / 好感单向累积 /
布尔 flags / 单一货币数值。**换题材名（校园、年代、穿越）不会改变这些结构**，必须同时扩两条轴：

| 轴 | 现有取值 | 需补的取值（示例） |
| --- | --- | --- |
| 题材 | 武侠 / 仙侠 / 赛博都市 / 太空科幻 | 校园 / 年代 / 穿越 / 职场 / 悬疑 / 西部 / 蒸汽朋克 |
| 语体 | 第三人称口语 | **书信体 / 日记体 / 报告体 / 群聊体** |

### 3.5.3 纪律：训练包与评测包**按轴不相交**

1. 训练包集合 **T** 与评测包集合 **E** 互斥（不同目录、不同 id、不同实体名）；

   数据集与评测报告记录 `pack_set_sha256`（训练集）与 `eval_pack_set_sha256`（评测集）。

## 4. Step 2 · 数据构造（3~4 天）

### 4.1 三源与配比

| 来源 | 占比 | 优势 | 坑与对策 |
| --- | --- | --- | --- |
| **YAML 程序合成** | 主干 60% | 零 API 成本、标签精确（程序推导）、**天然可扩域** | 语体偏干净、结构易单调 → 变化节点/NPC/数值规模，见 §4.4。**数据源 = 训练包集合 T（8~12 个新包，见 §3.5.5），不是现有三包** |
| **真实轨迹切窗** | 锚 20~30% | 生产分布真实（29K 上下文、压缩摘要、状态栏噪声） | **只覆盖现有包 → 唯一的窄化来源**，必须限量；与 T 的轴覆盖对照后按 §3.5.3 控制 |
| **flash 补标** | 10~20% | 唯一能产出真实叙事流的场景（compress/reflect/extract 需要） | 预算纪律 + **截断样本不得入库**（`complete_checked` 的 `truncated`）；**素材取自 T ∪ 生产锚**，不得取自 E |

### 4.2 五模块逐一：输入形态契约 + 标签 + 生成器

> **输入模板必须逐字对齐生产调用**（下面模板引自代码），否则训练分布与推理分布不一致。

#### 4.2.1 extract（P0，600~1500 对）

- **输入**（`game.py` `_extract_facts`）：
  - system = `EXTRACT_SYSTEM`（Step 0 去域化后）
  - user = `已有事实：{existing}\n\n<回合内容>\n{recent_8_turns}\n</回合内容>`
- **标签**：`重要性|事实` 行（1~10），≤5 条；无值得记的 → `无`；不得重复「已有事实」
- **生成器**：
  1. **程序化（主干）**：pack YAML 的 lore / npc 卡 / 事件效果 / 数值系统 → 生成"回合内容"
     （埋入已知的专名、数字、承诺、约定），标签 = 期望事实集（**精确**，可机器验证）；
  2. **轨迹切窗**：真实 recent 文本 + flash 补标（temp=0），抽检 5~10%；
  3. **负例（必配 ≥15%）**：纯日常寒暄回合 → 标签 `无`；已有事实的近义改写 → 亦为 `无`（考去重纪律）
- **覆盖要求**：10 类事实 × ≥3 题材，**数值类与承诺类各 ≥15%**（C 轴核心）

#### 4.2.2 judge（P0，500~1200 条）

> **家族配额（2026-09-12 按实测缺口定）**：confab **≥40%**、setting ≥25%、ooc ≥20%、
> 难例集 ≥10%；正常样本另按"误报口径"造（每题材 ≥40）。理由见 §1 与 §3.5.6c：
> 判官全部差距集中在 confab 一家（漏 ~70%），ooc/setting 已近满格。

- **输入**（`judge.py` `_judge_messages`）：
  - system = `JUDGE_SYSTEM`
  - user = `<材料>\n{materials}\n</材料>\n\n<最新叙事>\n{narration}\n</最新叙事>`
  - 材料 = `ContextBuilder.status_text(state, node)`（场景 / 在场 NPC / 好感 / 事实 / 记忆）
- **标签**：`通过` 或 `问题类型：描述`（≤2 条，引用叙事原文）

**confab 家族规格（本轮新定，主力家族）**：

- **判据**：材料里**不存在**该承诺/约定/事件，而叙事把它当作既成事实断言 —— 标签可**程序推导**
  （生成时该事实不入材料，标签必为"编造"），无需人工判断；
- **必须卡中性**（硬纪律，来自踩坑 #17）：promise 不得触碰说话人角色卡的
  `boundaries` / `forbidden` / `speech_style`，否则判官走"设定矛盾"第二通路 →
  拦截率虚高、跨包不可比（实测把同族用例从 27.5% 抬到 88%）。
  出厂前跑 `scripts/card_hook_check.py --gate`（词面筛查，**必要不充分**）+ 人读语义撞卡；
- **两档分层（都要造，但评测必须分切片报；`scripts/tier_slice.py` 可离线重切历史报告）**：
  - **T1 纯缺席**：材料零信号（无相关事实/记忆，好感与语气也不构成线索）——**核心难例**，占比 ≥50%；
  - **T2 语气冲突**：材料带"当前语气/好感"线索与承诺口气相悖（如好感 8/100「只聊作业」却许诺借车）
    —— flash 实测走此路很灵、14B 不走；两档标签同为 confab，但**混在一起报就又踩"多通路"老坑**；
  - ⚠️ **T1 必须专门造**（2026-09-12 切片实测）：机械规则一跑，P1 的 20 条里 18 条落在 T2 ——
    因为 NPC 初始好感普遍 5~10/100，而种子多是"示好/馈赠/私约"型承诺。
    要造出真 T1，二选一：① 用例里把说话人好感抬到中性/亲近档（`affections` 覆盖）；
    ② 用**事实断言型**而非示好型（如「那封信是我写的」「明天下午图书室不开门」）。
    `eval_quota_check.py` 会把 T1 占比 <50% 判为不达标；
  - **通路差异是能力信号，别丢**：flash 在 T2 上拦 94%（1/2 T1、17/18 T2），
    14B 在 T2 上只拦 22%（P1）——"低好感却示好"这条关系矛盾线，14B 基本不会用；
    这条差异应作为 T2 切片的固定报数项。
- **载体变体**：① 直接引语（`NPC说：『…』`）② 事后回忆（`…——这是你后来回想起来的，X 确实这样答应过你。`）
  —— 实测两种载体的漏判率无系统差异（两种变体都各有漏、各有拦），保留以免模型只认一种句式；
- **材料真值来源**：`facts` 留空 + 说话人在场（角色卡必进材料），确保通路只剩"缺席"这一条；
- **种子来源**：新手写（每包 ≥10 条，覆盖"借物 / 约同行 / 承诺代办 / 承诺引荐 / 赠物"等形态，
  形态与 `world-packs/*/judge_corpus.gen.yaml` 的 `gen_confab_promise_*` 对齐）+ 难例反向变体。
- ⏳ **待办（下一步）**：T1/T2 标签**目前还没落进语料**（P1/P2 v3 是两档混合）——
  "语气线索是否构成通路"是语义判断，机器筛不出来，故按 **种子作者标注** 写进 corpus 的
  `tier` 字段（生成器 + YAML schema 各加一个字段），并用机械兜底提示
  **好感 <20 且承诺含馈赠/私约类动词 → 疑似 T2**；回填后 §3.5.6c 的切片要按 T1/T2 重报。

- **生成器（其余家族，对抗样本标签可程序推导）**：
  - **setting（程序化）**：从材料里取一个事实（剑名/日期/地点/能力/身份），在叙事里改成矛盾值；
  - **OOC（半程序化）**：**必须从物化后的角色卡** `boundaries/speech_style` 出发改写语气或底线
    （star_ring 的教训：note 引用生成时的卡、物化后卡已变 → 漏判，见 `plan-worldpack-qa` §7.6.3）；
  - **normal（真实）**：真实轨迹叙事 + 对应材料，标签 `通过`；
  - **难例集（≥10%）**：从门禁报告 `hit=false` 的对抗样本反向构造同族变体
- **覆盖要求**：confab ≥40%、setting ≥25%、ooc ≥20%；每题材每类 ≥5；
  **T1/T2 两档在评测集里必须分开报数**（回归护栏 §6.3 也按此切片）

#### 4.2.3 compress（P1，200~500 对）

- **输入**（`game.py` `_compress_history`）：
  - system = `COMPRESS_SYSTEM.format(target=800)`
  - user = `<旧摘要>\n{existing}\n</旧摘要>\n\n<新增历史>\n{history_text}\n</新增历史>`
- **标签**：≤800 字 Markdown，保留 ①关系与好感 ②关键选择/承诺/约定（数字、名字、暗号、日期）
  ③重要事件与结果 ④未完成目标与线索 ⑤失败尝试与原因
- **生成器**：
  1. **程序化**：合成历史中埋入 K 个"必保全"要点（数字/专名/暗号/日期/承诺），
     参考摘要由模板生成（含全部 K 点），评测 = 保全率（规则抽取，`phase1_probe.eval_compress` 同款）；
  2. **真实形态**：轨迹首压 + 增量合并，flash 补标（`COMPRESS_MAX_TOKENS=4000`，
     **过滤 `truncated=true`**）；
  3. **长输入档 ≥20%**：20K 级输入（实测 14B 最弱 0.27，必须专门补）
- **负例**：含大量日常寒暄的历史 → 摘要**不应**出现寒暄关键词

#### 4.2.4 dedup（**仅评测集**，100~200 对）

- **输入**（`memory.py` `_is_semantic_duplicate`）：
  `<既有事实>\n{similar}\n</既有事实>\n\n<候选事实>\n{fact}\n</候选事实>`（bigram 预筛后触发）
- **造法**：同一事实 3 种改写（换词 / 换语序 / 换指代）→ `重复`；
  语义距离分级（远 / 中 / **近但不同**）→ `不重复`；
  含 bigram 边界样本（无重叠 vs 有重叠但不同）——顺带验证预筛不漏判
- **用途**：冻结回归护栏（训前训后都必须 100%，掉了即回退）

#### 4.2.5 reflect（P2，200~400 对）

- **输入**（`game.py` `_reflect_npc`）：
  - system = `REFLECT_SYSTEM`
  - user = `<角色>{name}</角色>\n\n<近期记忆>\n{numbered}\n</近期记忆>`
    （+ 可选 `<已有洞察>`）；素材 = 最近 12 条记忆，门控 ≥8 条
- **标签**：`洞察|来源编号`（编号必须命中素材序号）、≤2 条；信息不足 → `无`
- **生成器**：程序化关系模板（8~12 条记忆隐含"疏远→信任 / 信任→戒备 / 客气→依赖"等趋势），
  标签 = 带**正确编号**的模板洞察；补标档用真实记忆切片（temp=0）
- **负例**：素材不足或互相矛盾的记忆列表 → `无`；**来源编号错配**的样本必须能被判错（列入评测项）
- **批次**：数据照造（程序化档零 API 成本），但**第一批训练不含 reflect** —— 它不卡任何门禁、
  收益无法用现有仪器验证；训练排最后、可砍（见 §9 决策记录）

### 4.3 质量门（生成即校验，逐条）

| 检查 | 规则 |
| --- | --- |
| **契约 round-trip** | 标签过对应 parser 必须无损：`parse_facts` / `parse_verdict` / `parse_insights` / dedup 判词 |
| **截断/空/异常** | 补标样本 `truncated=true` 或空 → 丢弃；`无` 占比每模块设上限（防"全输出无"退化） |
| **单通路（对抗样本）** | **一条对抗样本只允许一条设计拦截通路**：confab 必须卡中性（`scripts/card_hook_check.py --gate` 词面零撞卡 + **人读语义撞卡**）；ooc/setting 不得顺带违另一条卡面规则。多通路样本只可留在**训练集**且必须打 `tier` 标签 |
| **配额（判据可判性的前提）** | `scripts/eval_quota_check.py --gate`：每包 ooc/setting/confab ≥20、normal ≥40、对抗合计 ≥60、confab T1 占比 ≥50%；不达标 → **该类判据不可判**（`0/18 = 0%` 的 95% 区间是 0~17.6%） |
| **轴覆盖（防"标签自欺"）** | `scripts/axis_coverage_check.py --gate`：声明表 `eval-sets/axis-coverage.yaml` 的机械字段必须与包实际一致（era/stats/NPC 数/主线节点数）；holdout 轴上 **T∩E = ∅**；新包未声明即失败 |
| **跨集合近似重复** | `scripts/near_dup_check.py --gate`：跨来源二字组 Jaccard ≥0.6 即报（防评测题泄漏进训练集、防"同句换人名"的模板同质） |
| **去重** | 与评测集 + 数据集内部做前缀/相似度去重（复用 `game.py` `_check_repetition` 的 0.6 阈值思路） |
| **配额** | 家族配额（§4.2.2）与轴覆盖矩阵（§4.4）每格 ≥N，未达标不出库 |
| **元数据** | 每条记录 `{source, pack, axis_tags, generator, seed, budget_policy, confab_tier(T1/T2)}`，便于后续切片分析 |

### 4.4 轴覆盖矩阵（"不窄化"的可检查形式）

| 轴 | 取值（示例） | 训练配额 | 评测留出 |
| --- | --- | --- | --- |
| 时代/题材 | 古代武侠 / 现代都市 / 太空科幻 / 仙侠 | 各 ≥15% | **民国谍战**（G1） |
| 语体 | 口语叙事 / 冷硬白描 / 技术术语 | 各 ≥10% | **书信体**（G2） |
| 实体类型 | 人名 / 地名 / 组织 / 物品 / 技艺 / 货币 / 信誉 | 各 ≥5% | 非中文姓名（G2） |
| 数值系统 | 银两 / 信用点 / 修为 / 声望 | 各 ≥10% | 信誉+声望混合（G2） |
| 关系动力 | 师门 / 雇佣 / 恋爱 / 亲情 | 各 ≥10% | **敌对型**（G2） |
| 违规形态 | OOC / 设定矛盾 / 虚构 | 各 ≥1/3（confab ≥40%，见 §4.2.2） | 混合形态（G1） |
| **可拦截通路数** | 单通路（纯缺席） / 双通路（缺席 + 语气关系冲突） | 单通路 ≥60% | **单通路为主**（卡中性纪律的推广，踩坑 #17） |
| 结构规模 | 节点 4~6 / 8~12 / 16+；NPC 1~2 / 3~5 | 覆盖三档 | NPC 6+（G2） |
| 输入形态 | 首压 / 增量合并 / 长输入(20K) / 脏输入 | 见各模块 | 脏输入（G1） |

> 规则：**每个轴至少有一个取值只出现在评测集** —— 这是"窄化"从担心变成可测指标的关键。

## 5. Step 3 · 训练（1~2 天）

- **适配器架构（2026-09-12 拍板 = 方案 A）**：同一底座权重 + **两个 LoRA 适配器** ——
  「侧信道组」（judge/extract/compress）与「主回合」（Phase 2 单独训）。
  主回合**永不挂**侧信道适配器：LoRA 不改底座权重，故侧信道训练不可能污染叙事；
  vLLM 多 LoRA 各自暴露为 model 名，引擎 `model_for(purpose)` 零改动即可路由。
- **混比**：`extract : judge : compress ≈ 4 : 3 : 2`（**dedup 0、reflect 第一批 0**）；
  每个 epoch 跨任务打乱，防任务块状学习；任务靠 system prompt 区分（已在库）。
- **序列长度**：侧信道输入 <10K（compress 可到 20K）→ 4090 QLoRA 可行（`plan-local-14b` D.7）。
- **可复现**：记录 seed / epochs / lr / 数据集 sha256 / `prompt_version`；**不做**主回合蒸馏（Phase 2）。
- **不动的东西**：`game_agent/budgets.py` 的预算常量（评测口径的一部分），如需改动则整套重测。

## 6. Step 4 · 评测（1 天）

### 6.1 三方对照协议

| 列 | 含义 | 命令口径 |
| --- | --- | --- |
| 基座 | 未训练 14B（Phase 0 已有初值） | 同命令 / 同 seed / 同 budget_policy |
| 训练后 | LoRA 模型 | 同上 |
| flash | 参照系（教师） | 同上，且不带任何 `DEEPSEEK_*` shell 前缀（§9.5 纪律） |

### 6.2 指标与判据

| 模块 | 指标 | 判据 | 泛化要求 |
| --- | --- | --- | --- |
| extract | 轨道事实保持率 / 期望事实召回 | ≥ flash − 5pp | G1+G2 均测（防"只认训练题材"） |
| judge | 每类拦截率 / 误报率 | 拦截 ≥ `INTERCEPT_MIN=0.80` 且 ≥ flash−5pp；误报 ≤0.10 | 同上；G2 强制 |
| judge · **confab 切片** | **T1（纯缺席）/ T2（语气冲突）分开报** | **T1 ≥0.60 视为起步、目标 0.80**（零样本仅 27.5~32%，是主战场） | 每包/每题材都要报，禁止只报家族平均分 |
| compress | 保全率 / 结构合格率 / 截断率 | 保全率 ≥ flash−10pp；截断率 0 | 长输入档必须包含 |
| reflect | 洞察合法率 / 矛盾率 | 合法率 ≥80%；矛盾率 0 | 来源编号正确性单列 |
| dedup | 拦截率（冻结集） | **必须 100%（回退即失败）** | — |

### 6.3 回归护栏（任何一项失败即判训练有害）

1. **A 轴协议不许退化**：`worldpack_smoke` 两包通关 + 熔断率不升 —— 性质是**部署配置检查**
   （方案 A 下底座权重不动、主回合不挂侧信道适配器，侧信道训练本身不会伤主回合；
   但适配器挂错 / 路由配错会当场崩）；
2. **dedup 冻结集必须 100%**；
3. **门禁四连**（`check-worldpack` / `pytest` / `judge_sensitivity` / `worldpack_smoke`）全绿；
4. **契约合规**：输出过 parser 的失败率为 0（`无`/`通过`/`洞察|编号` 等格式）；
5. **confab 单通路切片不许掉**：judge 回归必须分家族报，其中 **confab 的 T1（纯缺席）子集单列** ——
   这是当前最弱一环，最容易被 ooc/setting 的高分平均掉（§3.5.6c）；该子集掉点即判训练有害。
   评测语料改动后**两侧都要重测**（flash 参照线 + 14B 探针，换尺子不换两侧 = 假对比）；
6. **数据守卫三连**（可入 CI，任一 FAIL 即停）：`eval_quota_check --gate`（配额=判据可判性）、
   `axis_coverage_check --gate`（轴声明 vs 事实 + T∩E 不相交）、`near_dup_check --gate`（防泄漏/模板同质）。
   首跑结果见 `eval-sets/MANIFEST.md` §9（配额 6/6 未达标、结构轴未留出、2 对模板级近重复）。

### 6.4 报告 schema（新增字段）

```json
{
  "budget_policy": "budgets.py@<sha>", "prompt_version": "<hash>",
  "endpoint": {
    "base_url": "http://127.0.0.1:8000/v1", "model": "local-14b",
    "served_by": "vllm", "model_root": "Qwen/Qwen2.5-14B-Instruct-AWQ",
    "max_model_len": 32768
  },
  "category_filter": ["confab"],
  "train_set_sha256": "...", "eval_set_sha256": "...",
  "summary": { "<cat>": {"n": 0, "hits": 0, "rate": 0, "unknown": 0} },
  "baseline": "zero-shot | flash"
}
```

> `endpoint` 是**部署指纹**（`game_agent/endpoint.py`）：只记 `model` 分不清"哪次部署"——
> 换量化/换后端/换窗口后历史数字无法对账；云端口径还会出现别名
> （`deepseek-v4-flash` 实为 `deepseek-flash`，指纹记 `not_listed` + `available` 留痕）。
> `category_filter` 非空 = **部分类别运行，不是门禁口径**（不得当"门禁通过"读）。

> 记录 `budget_policy` 是 2026-09-11 的教训：`judge_sensitivity_*.json` 没记预算策略，
> 导致"40-50%"是哪个配置时代的产物无法分辨。

### 6.5 决策门 1（落地版）

  （flash 兜底），不阻塞主线。

## 8. 风险与对策

| 风险 | 表现 | 对策 |
| --- | --- | --- |
| **窄化**（题材/语体/结构） | 泛化包掉点，训练包虚高 | **§3.5 世界包覆盖**：轴级留出 + 训练包集合 T（8~12 新包）作数据主干 + 轨迹限量 + 零样本跨包对照先量化 |
| **过度扩域** | 只会处理"模板味"干净文本，真实脏包退化 | 保留真实包锚点（20~30%）+ 合成包结构多样化 |
| **五任务干扰** | 某任务提升、另一任务回退 | 混比设计 + dedup 不进训练 + 每模块单独评测 |
| **评测污染** | 训练集混入评测前缀 → 虚高 | 前缀级指纹去重 + 评测集冻结 + sha256 记录 |
| **尺子口径漂移** | 不同 run 的预算/提示词不可比 | `budget_policy` + `prompt_version` 写进报告 |
| **补标截断污染** | 截断输出被当标准答案 | `complete_checked` 的 `truncated` 过滤；compress 预算 ≥4000 |
| **判官标签与门禁打架** | 训练后 judge 与 `judge_sensitivity` 判据不一致 | 标签定义直接对齐 corpus 的 `category/expected` 语义；契约测试 |

| 6 | confab"缺席证据"是否升为判官一等训练家族（2026-09-12 由 §3.5.6c 判决性实验提出） | **是**：同难口径实测该家族拦 27.5~32%（**漏 ~70%**），错法与题材/包无关，而 flash 能拦 82~90% → 是学生模型最该补的一课。judge 优先级由"P0 小补强"**升级为"P0 必训"**，训练配额 **confab ≥40%**，评测必须按 T1（纯缺席）/T2（语气冲突）**分切片报**（§4.2.2 / §6.2 / §6.3） |

| 9 | 尺子要改时，已有测试/基线怎么办（2026-09-12 用户提问） | **加性扩展 + 版本自证 + 一次重测**：既有条目文本不动（老数字永久有效，作 v1 切片并排报）；报告写 `content_version` / `case_set_digest` / `endpoint` / `category_filter`；所有语料改动攒齐后两侧各重测一次；能离线重切的（如 T1/T2 切片）绝不重跑（`eval-sets/MANIFEST.md` §8） |
| 10 | 开工前先补守卫还是先造数据（2026-09-12 用户提问） | **先补守卫**：`eval_quota_check`（判据可判性）/ `axis_coverage_check`（T∩E 不相交 + 声明 vs 事实）/ `near_dup_check`（防泄漏）三件本地零成本；首跑即抓出 6/6 包配额不足、结构轴未留出、2 对模板级近重复 —— 带着这些洞去造数据 = 造完才知道尺子不可判 |
