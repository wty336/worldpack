### 1.1 N2a 与 N6 的边界：按"面"切，不按"前端 / Agent"切

**为什么要专门写这一节**：N2（创作工作台）与 N6（创作者 Agent）看起来像两件会互相打架的事——
一个做界面，一个做对话式改卡。读 roadmap 的字面会得出"先做表单工作台、之后再加 Agent"，
**而那个顺序会白做一块**。真实关系在 `plan-tavern-shaped-product.md` §5.1 里已经画出来了：

```
工作台 1：卡片/包库（浏览、选、导入）
工作台 2：编辑器（左边对话、右边字段与校验报告）
```

**"左边对话"就是 N6，"右边字段与校验报告"就是 N2 的报告面——它们本来就是同一个屏幕的两半。**
是"N2 前端 / N6 Agent"这种按技术层拆的写法，把一件事读成了两件。

**会白做的那一块是"手写字段编辑器"**（表单改 NPC 卡 / 世界书）。理由有三条，任一条都够：

1. **§4.1 的整个论证就是"结构化 CRUD 交给 Agent 比表单好"**——同一份文档里既说"表单不合适"、
   又排一个表单工作台，自相矛盾；
2. **用户的原话是"与 Agent 对话…修改人物设定和世界书"**——对话式才是要的目标，表单不是；
3. **表单会和草稿抢同一份真值**。Agent 改完草稿之后，表单里显示的是它上一次读到的值；
   要么表单得跟着 agent 的工具调用实时刷新，要么两边不一致。这是纯粹的 UI 状态同步债，
   换不来任何能力。

**所以按"面"切**：

| 面 | 归谁 | 内容 |
| --- | --- | --- |
| 生成流程 | **N2a** | 贴素材 → SSE 进度 → 取消 → 校验报告（含修复轮报错原文） |
| 草稿生命周期 | **N2a** | 草稿列表 / 试玩 / 发布 / 删除（后端 E-7 已就绪） |
| 显示面 | **N2a** | 右栏**只读呈现**字段、计数、`digest`、校验结论与 diff |
| 编辑面 | **N6** | 对话 + 工具轨迹 → 改草稿 → `validate_pack` → 报错回灌 → 再校验 |
| 记账 | **N6 开工即做** | Agent 调用要带按包/按会话的归因轴，否则重演 G-6 串号 |

**顺序**：N2a → N6。反过来的话，Agent 改完草稿没有任何地方看 diff 与校验结论，等于闭着眼改。
先做 N2a 不会返工——生成流程与报告渲染**本来就是 Agent 的显示面**。

### 2.1 N1 执行记录（2026-10）：后台任务 + 进度 SSE

**交付**：`game_agent/jobs.py`（任务表 + 串行执行器）+ 5 个端点 + `tests/test_jobs.py`（22 项）
+ `scripts/worldgen_smoke.py`（真机 SSE 冒烟）。

**为什么不能照抄 `_turn_stream`**：那个流是"一个请求 = 一个回合"——秒级、单一消费者、
断了就断了。生成是**分钟级**任务，形状根本不同：

| | 回合流 | 生成任务 |
| --- | --- | --- |
| 消费者 | 一个 | 可能多个；**刷新页面后还要能接上** |
| 断线 | 回合照跑，没人再看 | **必须能重连并看到已发生的全部进度** |
| 结果 | `done` 帧带完整视图 | 是个目录 + 一份成本报告，要能**事后**取 |

于是三件具体的事：
1. **事件留档 + 回放**（`job.events` 是事实来源，订阅时先回放再续播）——
   分钟级任务里刷新页面是常态，不是边缘情况；
2. **多订阅者广播**，慢消费者**只丢自己**（有界队列 + 省略提示），不阻塞生产者、
   不影响留档；
3. **取消**，检查点在**块与块之间**——一次 LLM 调用中途没法安全打断，也不该打断
   （半截响应没有意义，而钱已经花了）。取消落成 `cancelled` 而**不是** `failed`
   （取消不是失败，这是排查时第一个要看的信息）。

**四条护栏**（都是"能被脚本调用"才需要的，CLI 不需要）：
- **拒收文件路径**：接口只收 `source_text`。若收 `sources: ["../../.env"]`，就是一个
  任意文件读取洞（`read_sources` 会老实读出来喂给模型）；CLI 收路径没问题，那是本机
  用户手敲的。
- **拒绝覆盖同名包**：`materialize` 会先清空 `npcs/`，同名写入等于静默毁掉一个已发布的包。
- **并发上限 1**：同时跑两个生成只会两边都慢、费用翻倍且难以归因；排队是显式的
  （`status="queued"`），不是静默等待。
- **取消排队中的任务不发车**（否则白烧一次生成）。

**一个实测发现值得记住**：`TestClient` **会缓冲整个 SSE 响应体**——用它测"首末到达
间隔"恒为 0，那是客户端在缓冲，不是服务端。这一点是绕过 HTTP 直接消费 `_job_stream`
确认的（同一段代码，实测首末间隔 0.297s，与合成的 50ms×6 完全吻合）。
所以增量性守卫放在**生成器层**（`test_job_stream_yields_incrementally`，合成慢任务、
确定性），并额外留了一条 `test_testclient_buffers_sse_...` 当路牌——否则后来人会加一条
HTTP 层断言、得到假红，然后去改本来正确的服务端代码。
**已用变异验证**：把 `_job_stream` 改成"先睡到任务结束再发"，该守卫立刻变红。

**验证**：离线 **959 项全绿**；真机 SSE 冒烟 12 项全通过 + 1 项**如实报"不可判"**
（离线生成仅 0.09s，HTTP 链路增量性测不出——按 `test_qa_gate.py` 的纪律
"全部被跳过 ≠ 通过"，不可判就报不可判，不冒充通过）；冒烟自清理产物。

**遗留限制（已在 §2.2 解除）**：接口当时**拒绝覆盖同名包**（`materialize` 先清空
`npcs/`，同名写入等于静默毁掉线上包）。代价是"改一版再生成"只能不停换名字，
`world-packs/` 里会堆出 `foo` / `foo2` / `foo_new2`。

### 2.3 N2a 执行记录（2026-10）：创作工作台的共享外壳

这条决定落成了一条**可执行断言**——冒烟直接断言"右栏输入框数量 = 0"。
设计决定写在文档里会被后人改掉，写成断言才会拦下来。

#### 三条设计判断

1. **"离线试跑"默认勾上**。真实生成一次约 ¥0.1–0.3，作者第一次点进来多半只是想看
   这条链通不通——**默认值就是产品决策**，默认让人花钱是错的默认值。取消勾选时有一句
   醒目的成本提示。这一条在**浏览器里**做过变异验证：把默认值改成 `false`，
   冒烟立刻 35/36。
2. **进度流的断线语义与回合流**相反**，两者结论不可互搬**：

   | | 回合流（POST） | 任务进度流（GET） |
   | --- | --- | --- |
   | 断线重连 | **会把回合重跑一遍**（重复扣费/落盘）→ 禁止 | 只是重新订阅，不重跑任何东西 |
   | 重连后收到 | 新的一回合 | 服务端**先回放全部历史**再续播 |

   所以这里仍然不用 `EventSource`（它的自动重连是无状态的，会让每次重连重收一遍历史），
   而是**有上限的显式重连**；且重连时**从空列表重建**日志——因为服务端总会回放完整历史，
   "重复行"这个问题在结构上就不存在，**不需要去重代码**。
3. **修复轮的报错原文来自 N1 的事件留档**（`repair` 事件），刷新页面后仍能回放。
   这是"事件留档 + 回放"的第二次兑现（第一次是后台任务自身）。报告栏把
   `stages / repairs / corpus_written / summary / cost` 一起呈现。

#### 三次假绿，同一个形状（本次最值得记的教训）

写这批守卫时**连续三次**写出"看起来在守、其实什么都没守"的断言，形状完全一样：
**把"某段代码存在"断言成"这个字符串在文件里出现过"**，于是被别处的同一字符串满足。

| # | 断言写法 | 被什么满足 | 改成 |
| --- | --- | --- | --- |
| ① | 源码里必须有某判据 | **注释** | `ast.unparse` 剥掉注释再查（§2.2 已记） |
| ② | `say(e.message, true)` 在文件里 | **别的 catch 块**也有这行 | 限定到 `publish()` 函数体内 |
| ③ | `method: 'DELETE'` 在文件里 | `del` **辅助函数的定义** | 检查 `deleteDraft` 的**调用点**用什么 |

前两次都是"改了被测代码、守卫照样绿"（用变异才发现）。已升格为 §4 纪律 7：
**断言要限定到"发生位置"，不是"文件里出现过"。** 配套加了 `tests/test_web_frontend.py`
的 `_function_body()` 助手。

#### 另一个洞：桩会同意我关于后端的假设

浏览器冒烟用**桩后端**（不花钱、可重复），代价是它由我手写——**我把响应键记错，
桩就照着我错的样子实现，冒烟照样全绿，而真机上是一片空白**。
补了 `test_workbench_payloads_carry_the_fields_the_view_reads`：用**真** app 跑一次
离线生成，逐个断言前端读的键真的存在（`job_id` / `cost` / `result.repairs` /
进度事件的 `stage,message` / 草稿项的 12 个键 / 开局的 `draft` 标记）。
**已变异验证**：把快照里的 `cost` 改名 → 立刻红。

### 2.4 N6 / E-8 执行记录（2026-10）：创作者 Agent（能力 C）

**交付**：`game_agent/creator.py`（工作版 + 11 个工具 + 修复循环 + diff）
+ `catalog.fork_to_draft`（把已发布卡复制成草稿）+ `LLMClient.complete_with_tools`
+ `Settings.creator_model` + `UsageTracker(pack=…)` 归因轴
+ 4 个端点（`POST /api/packs/fork`、`GET/DELETE /api/creator/{name}`、
  `POST /api/creator/{name}/chat`）+ 前端对话面板/diff/两模式页签
+ `tests/test_creator.py`（33 项）+ `scripts/creator_smoke.py`（真机对话冒烟）。
**逐条推理见 `plan-tavern-shaped-product.md` §6.8。**

#### 为什么是**另一条**循环，而不是往 `game.py` 里塞

`llm.run_turn` 是为**叙事回合**优化的（流式正文、`submit_narration` 收尾协议、Judge、
内轮自校正、整轮原子回滚）。创作者任务是**结构化 CRUD**，形状完全不同：

| | 叙事回合 | 创作者回合 |
| --- | --- | --- |
| 收尾 | 必须调 `submit_narration`，否则熔断 | **不调工具 = 说完了**（没有协议） |
| 质量兜底 | Judge + factcheck + 回滚 | `load_worldpack`（硬门禁，与发布同源） |
| 失败代价 | 整轮作废、玩家看到兜底文本 | 改坏了再改一次——**草稿就是沙箱** |

**但复用同一条 LLMClient**：模型路由、usage 记账、trace 只有一份实现。
否则创作者线会自己长出一套记账——那正是 G-6（记账串号）的形状。

#### 三个关键判断

1. **工作版 = 草稿目录本身**，不另做一份副本。E-7 已经把 `_drafts/<name>/` 定义成
   "随便改、过闸门才能发布"的区域；本模块里**没有任何一行**写已发布区
   （真机冒烟用"改前改后各取一次 `pack_digest`"来证明这一点）。
2. **基线取"会话第一次碰到它时"的内容**，不是"已发布区里同名的那份"——
   生成的草稿根本没有已发布版本，而作者真正要看的是"**Agent 改了什么**"。
3. **白名单 + 整体校验**。字段白名单挡住"模型手滑写个不存在的字段然后静默丢失"；
   `load_worldpack` 挡住"改完之后玩家一定会撞上"的问题，且**报错原文回灌给模型**
   ——这就是 §4.2 说的"修复循环的燃料"。
   `validate()` 用的就是发布闸门那一次加载，所以**不会出现"Agent 说通过了、发布被拒"**。

#### 真机跑出来的三件事（本次最有价值的部分）

**① 真实模型**真的**按 read → 改 → validate 走**：
`read_npc → list_npcs → read_npc → update_npc_field → validate_pack`，9 帧 / 4.7s /
6 次调用 / 13,822 tokens（≈ ¥0.002）。§4.2 赌的"validate_pack 是支点"成立。

**② 第一次跑"失败"了，而失败的是冒烟指令。** 第一版提示词写的是
"把**主角**的说话风格改得更简短克制一些"——模型读完世界后**拒绝猜**，回答：
"本包只有 1 张角色卡（沈清秋），**「主角」是玩家角色**，只存在于 `world.player_role`"，
并反问要改谁。**这恰好是设计意图被验证了**（系统提示里就有"问清楚再动手，
比猜错一遍再回滚便宜"），坏的是指令有歧义。
> ⚠️ **教训**：冒烟指令的歧义会被记成产品缺陷。真机冒烟要**指名道姓**
> （点名 npc id 与字段），否则你测的是"模型怎么理解你的模糊话"，不是"链路通不通"。

**③ 桩会同意我（N2a 记过一次，这里是同一个洞的另一面）**：
浏览器冒烟用桩后端，我把 done 的字段名记错、桩就照错的样子实现。
已补 `test_workbench_payloads_carry_the_fields_the_view_reads_creator`（用**真** app
跑一轮脚本化对话，逐个断言键存在）与 `scripts/creator_smoke.py`（打**真**模型）。

#### 踩到的坑（四个，其中两个是"我自己写的假绿"）

1. **`WorkingCopy` 基线为空时，`diff()` 把每个存在的文件都算成"新增"**
   （旧侧是空串）→ 作者看到一份"改得面目全非"的 diff，而实际什么都没改。
   修法：`__post_init__` 取基线，让"没有基线的工作版"**构造不出来**。
2. **`add_npc` 的返回文本说错了因果**：原写"不登记 `affections` 会被 check-worldpack
   拒绝"，实测闸门只校验**反方向**（`affections` 指向的角色卡必须存在），
   有卡没登记是合法的。**给模型一条错的因果，比不给提示更浪费时间**——它会白做一件事
   然后发现自己没做错什么。
3. **冒烟断言词序写反**：右栏渲染的是 `✗ check-worldpack 未通过`，而断言等的是
   `/未通过 check-worldpack/`。那次"失败"是断言 bug，不是产品 bug。
4. **我自己又写了两处假绿**：`assert "... " in v and "..." not in v or True`（`or True`
   让它恒真）与 `pack_digest(X) == pack_digest(X)`（恒真式，同一路径当然等于自己）。
   都已删掉换成真断言。**这是本仓库第四次/第五次同一形状的坑**——
   纪律 7 因此再补一句：**写断言时先看它有没有可能不成立**。

### 2.5 补记（2026-10）：对话式做卡 + 真机通关暴露的两个引擎 bug

用户问"现在能实现那些功能了吗"时，逐条核了一遍，发现**一个字面缺口**与**两个真 bug**。

#### ① 对话式做卡：`start_generation` 工具（缺口已补）

原先"从素材制作新卡"只有**表单**路径（工作台页签①），Agent 的 11 个工具里没有
一个是"跑生成管线"——用户说"把这段大纲做成一张卡"，它做不了。而需求原话是把
"与 Agent 对话"和"从素材制作新卡"连在一起说的。

补法是**转交**而不是代跑：生成是分钟级任务，塞进一次工具调用里同步等会把一轮对话
挂死几分钟且看不到进度。工具只做四件事：校验参数 → 丢进已有任务表 →
推一个 `job` 事件（前端据此**自动切到进度页签并订阅那条流**）→ 告诉模型**别等**。
未接入时工具以 `disabled_msg` 明确拒绝（"不要假装你能生成"）——挡的是最坏的失败：
模型凭空答应"我这就做"，然后什么也没发生。

#### ② 两个引擎 bug：关键抉择期的**卡死**（已修）

真机跑生成卡时两次撞到 `GameError: 此刻是关键抉择，只能从固定选项中选择`。
两次形态不同，根因是同一个：**视图与引擎状态自相矛盾**。

| # | 触发形态 | 引擎状态 | 视图原先说什么 |
| --- | --- | --- | --- |
| 1 | 抉择的 `pick()` 生成熔断 → 事务回滚把 `pending_choice` 还原（设计如此：熔断不该吃掉一个分叉） | 仍锁着 | `choice_prompt=None`（熔断兜底没带，**带上后又被 `_narrate` 的聚合丢掉**） |
| 2 | `end_turn` 完成节点后找下一个满足 `when` 的节点；生成器写出的节点 `when: {all: []}` **恒真** → 同一节点立刻重入 → 又挂上待决抉择 | 又锁上 | 返回值只搬了 `narration/choices/ending` |

后果同一种：`say` / `act` / `end_day` **全抛 GameError**，而唯一的出路 `pick(i)`
**在界面上没有按钮可点**——Web 玩家彻底卡死，只能读档。

**修在 `_narrate` 的出口**（所有回合的唯一汇聚点），判据从"上游视图带了什么"改成
"**引擎现在到底锁没锁**"（`story.pending_choice(state)`，与 `choice_locked` 同源）：
锁着就把 `choice_prompt` 与选项文本一起给出去。逐个出口去补是治不完的——
这一批撞到两个出口，下一批还会有第三个。

> 这条也顺带解释了冒烟脚本为什么崩：它看到 `choice_prompt=None` 就去调 `act()`，
> 于是撞上锁。修好引擎之后**脚本不用改**——把脚本改成"绕开"反而会把 bug 盖住。

#### ③ 生成卡的结局在实践上够不着（**未修，已立为 N12**）

真机（`deepseek-v4-flash`）把这张离线生成的卡玩了 15 天：**主线推进正常**
（节点完成旗标 `met_lin: true` 写入）、数值零偏差审计通过、禁表通过——
但**没通关**：好感只到 13，而结局要 `lin >= 50`。

原因不是模型不努力，是这张卡**没有任何行动能提升好感**：
`visit_lin`（拜访林）的 `effects: {}` 是空的，`work`（接单）只给信用点，
`events: []`。全程唯一确定性增益是那个一次性 +3 的关键抉择。
剩下的路只有叙事者的 `change_stat`（每次 ≤±5 且要有剧情理由），15 天累计 +5。

而 `check_worldpack` 的数值可达性门禁**没拦住它**：那道检查被 `if _day_hits:` 包着
——**只有当某个结局带 `day` 门槛时才跑**，而生成器写出的结局恰好没有 day 门槛。

**注意别把它说成"确定不可达"**（第一版我这么说，是错的）：`change_stat` 是一条
重复路径，所以严格说只是"**确定性路径为零**"。判据怎么立、以及该修门禁还是修生成器，
见 **N12**。

### 2.6 N7 / G-2 执行记录（2026-10）：存档点 · 回退 · 分支

**交付**：`game_agent/timeline.py`（时间线模型）+ 每回合自动建点 + 3 个端点
（`GET /api/{sid}/timeline`、`GET /api/{sid}/history`、`POST /api/{sid}/rewind`）
+ 左栏时间线与「回到这一版」+ 回退后重建正文栏 + `tests/test_timeline.py`（16 项）。

**这是玩家侧唯一还缺的体验**：此前玩错了只能读档、回不到上一回合。对标文档把它标成
**G-2 / P0**，而且它的地基早就在——`runlog` 已有回合级全量 checkpoint。

#### 为什么不能直接复用 `runlog`（一句话）

`runlog` 按 **turn** 命名快照（`checkpoints/{turn:06d}.json`）。玩家面里这会**撞死**：

> 回退到第 5 回合 → 继续玩 → 又走到第 6 回合 → **`000006.json` 被覆盖**，
> 旧的第 6 回合永久消失，而玩家以为自己开了个分支。

所以本模块按 **revision（只增不减）** 编号。这是 G-2 的**核心数据结构**，不是实现细节。
`runlog` 一行没改，两者分工：它是实验线，`timeline` 是玩家线。

#### 四条语义（直接采用 dsh-tavern 踩过坑的结论）

1. **revision 只增不减**：回退**也**产生新版本（`rev = max+1`）。若 rev 可以回退，
   就会出现"同一个 rev 先后指向两份不同内容"，于是"上周那一版到底长什么样"再也答不出来。
2. **回退即开分支，旧分支原地不动**：新 `branch`（`b2`…）+ `parent` 记来源；
   旧分支的条目与快照**一个字节都不动**，且**没有任何读取路径会碰它**。
3. **state / history / rng 三者一起还原**。`rng` 尤其不能漏：检定掷骰、`chance` 日程事件、
   `{base, spread}` 收益曲线都吃它——不还原的话，回退后的世界会从**另一个随机流**继续长，
   玩家的观感是"回退了但世界变了"。序列化口径复用 `runlog.rebuild_game`（元组回环）。
4. **派生失败不阻塞**：建点写在回合**提交之后**，所以写盘失败**不得**让这一回合失败
   （与 ADR 0006 同款纪律）。玩家看到一句提示，而不是"这一回合白玩了"。

#### 三个踩到的坑（都是"看起来对、其实悄悄错"的形状）

1. **回退差点把构造选项一起退回默认**。`runlog.rebuild_game` 用的是
   `Game(pack, state, llm, rng=…)`——**全是默认值**。直接用它，回退一次就会把
   `mainline_enabled`（自由模式）、`context_window`（溢出预检）、`critique_on_critical`、
   `factcheck_every` **一起静默退化**，玩家只会觉得"回退之后手感变了"。
   修法：把选项抽成 `web._game_options()`，**建局与回退共用一份**；
   并给那条既有的接线守卫加了"两个入口都必须用它"的断言。
2. **正文不在 `history` 的 `content` 里**。引擎协议是"模型调 `submit_narration` 提交正文"，
   所以那条 assistant 消息的 `content` 是**空串**，正文在**工具调用的 arguments** 里。
   按 `content` 取的结果是"重建出来的故事栏只有玩家自己的话"——看起来像"历史丢了"，
   其实是取错了地方。`_narration_of()` 就是为此存在的。
3. **测试把 21 个时间线目录漏进了仓库的 `saves/`**（0.4 MB）。根因有两层：
   - 表层：web 测试按**文件名**清理自己的产物（`unlink(missing_ok=True)`），
     而时间线目录名带**随机会话号**，测试没法按名字清；
   - 深层（潜伏 bug）：`_usage_path` / `autosave_path` 写死了 `"saves/..."` **相对字面量**，
     不是从 `SAVE_ROOT` 推的——所以"把 `SAVE_ROOT` 重定向到临时目录"这种隔离手段
     **盖不住它们**，账本/自动存档/时间线会各走各的，而且不报错。

   两处都修了：新增 `tests/conftest.py` 的 autouse 夹具把 `SAVE_ROOT` 指到每测试的
   临时目录（顺手也治好了**既有的** `autosave-<hex>.json` 泄漏），并把三处会话级产物
   统一改成从 `SAVE_ROOT` 推导。**验证方式**：清空 `saves/` 里的会话级残留 → 跑全量 →
   再查 `timeline-*` / `autosave-*` / `usage-<hex>` 均不再出现。

#### 边界（如实记）

- 时间线**按会话**索引，而会话是进程内状态：服务重启后旧的 `saves/timeline-<sid>/`
  不会被自动接回（`saves/autosave-<sid>.json` 仍然覆盖"恢复这一局"这个需求）。
  要"重启后还能从时间线挑一版继续"，需要再加"列出磁盘上的时间线 + 从某一版开会话"
  ——**没做**，记为后续。
- 时间线目录已在 `.gitignore`（`saves/timeline-*/`）——与 `autosave-<sid>.json` /
  `usage-<sid>.jsonl` 同一形状（名字带随机会话号，跑一局就多一批，不是证据）。
- 保留策略是**全都留着**（G-2 的价值就是"回得去"，静默丢历史会直接摧毁它）；
  占用通过 `GET .../timeline` 的 `size_bytes` 暴露给前端，让人自己看得见。

#### 验证

- 离线 **1048 项全绿**（`test_timeline.py` 16 项为新）。
- **变异验证 2 处**：① 回退不记 `parent` → 3 条守卫变红；② 回退时截断旧分支
  （= `runlog` 那种按 turn 覆盖）→ 2 条守卫变红（含"旧分支一个字节都不动"）。
- **真机浏览器冒烟 50 → 58 项**：时间线渲染 → 当前版本被标出 → 条目带分支与标签 →
  当前版本不可点（回退到自己是空操作）→ 点「回到这一版」→ 提示说清"新版本 + 新分支 +
  原来的线还在" → **正文栏被重建**（不是留着已经不存在的旧剧情线）。
- 顺带：改了 `_turn_stream` 的签名（多一个 `sid`），三处直接调用它的测试跟着改；
  其中 `test_overflow_recovery` 的接线守卫**跟着改指向并查得更严**（见坑 1）。

### 2.7 N12 执行记录（2026-10）：生成卡的"机制上够不着"结局

**交付**：`worldpack` 可玩性门禁第 10 项（无预算子判据）+ `worldgen` 的修复路由与冒烟
动作选择 + `tests/test_worldpack_playability.py`（+7 项）/ `tests/test_worldgen.py`（+2 项）；
**并修好了 fixture 里长着的同一个缺陷**。

#### 判据：区分**可重复**来源与**一次性**来源

第一版判据我写成"该维度没有任何确定性增益来源 + `initial < 阈值` → 拒"。
拿真机那张卡一测**它放行了**：`gen_probe` 的好感被判为"有来源"——因为关键抉择的 **+3**
算确定性来源。可那是一次性的（5 → 8），而结局要 50。

所以判据必须是：

> 若某维度**没有任何可重复的增益来源**（日程行动 / 自定义工具都不涨它），
> 那么它的上界 = 「初始值 + 一次性来源加满」（关键抉择每个只选一个取最大、事件累加）。
> 这个上界 < 阈值 → **机制上够不着**。

这条**不需要天数预算**——而这正是关键：原来的步骤 6 被 `if _day_hits:` 包着，
**只有某个结局带 `day` 门槛时才跑**，而生成器写出的结局恰好没有。

#### 口径要诚实（写进报错原文）

判的是"**机制上够不着**"，**不是**"绝对不可达"——叙事者仍可逐轮用 `change_stat`
调整好感（每次 ≤±5）。但那是模型的自由裁量，不是"玩家照着玩法走就能到"。
结局阈值应当由机制兜住，所以按错误处理。**报错里同时给出这句话**，
免得下一个读代码的人（或模型）把它当成"数学上不可能"。

#### 三个实现细节，都是踩过才知道

1. **跳过 `any` 与 `not``**：步骤 6 用的 `_numeric_conditions` 把 `any` 的分支也当要求
   （对"要求"保守，但对"够不着"**会误报**——`any: [affection ≥50, day ≥3]` 里好感那支
   够不着不妨碍结局达成）。所以另写了 `_hard_numeric_conditions`，只走无条件路径。
2. **修复路由必须同时指两处**：`repair_sections` 是**有序关键词**匹配，而这条错误的
   文本里同时有"结局"和"行动"——不特判就会被 `行动` 抢走，只重生成 `schedule`，
   模型永远想不到"也可以降阈值"。而**降阈值恰恰常常是更好的那个修法**。
3. **爆炸半径先量再写**：动手前先跑探针确认"新判据会不会拒掉现有 8 张卡"。
   结果 **8/8 全过**（它们每个结局要求的维度都有行动在涨），而生成的那张被准确拦下。
   这条探针本身就是"门禁过严"方向的第一道验证。

#### 附带发现：fixture 里就长着这个缺陷

新门禁一加，`tests/test_worldgen.py` **20 条全红**——因为离线假 LLM 的
`_offline_pieces()` 里，`visit_lin` 的 `effects` 就是 `{}`，而结局要 `lin >= 50`。
**门禁是对的、fixture 是坏的**，所以修 fixture（给它加 `affections` 增益而不是放宽门禁）：
真实提取器产出的"拜访某人"行动本来就带好感增益，空 `effects` 才是异常形状。

顺带修了 `smoke_profile` 的两处不自洽：它原来一律取 `actions[0]` 当冒烟动作
（`work`，只给信用点），而目标结局要好感——**画像与目标天然可能对不上**。
现在按"结局条件里要涨的维度"挑行动（`_action_toward`，挑不到回落第一个）。

#### 免费的那一半：生成卡**现在能真通关**

修完之后，离线生成的卡在 `worldpack_smoke --offline` 里真的走到了结局：

```
好感 15.8 → 24.0 → 33.7 → 41.6 → 49.6 → 【结局】留下
[✓] 数值零偏差审计通过（7 条变更记录）   [✓] 禁表扫描通过
```

这把 §2.5 ③ 里那句"**生成卡真机通关未达成**"从"要花钱的一次性实测"变成了
**可重复的零成本验证**——比原来那次付费尝试更有价值。

#### 验证

- 离线 **1048 项全绿**（N12 相关 +9 项：门禁 7 + 生成器 2）。
- **变异验证 2 处（两个方向都验）**：① 判据停用 → 核心断言 `DID NOT RAISE` 变红；
  ② 把所有来源都当成"不可重复"（过严）→ `P1_school_letters` 被拒 →
  "不误伤现有 8 张卡"那条守卫变红。
- 真机浏览器冒烟 **59/59**（本项无前端改动）。

## 4. 纪律（改代码时照着做）

1. **改完必须跑离线全量**（1048 项）；前端改动还要跑 `node scripts/webui_smoke.mjs`。
2. **改了 `game_agent/webui/src/**` 必须 `npm run build`**——`dist/` 入库，忘了重建测试会红
   （`tests/test_webui_build.py` 用内容哈希判定，不依赖 mtime）。
3. **守卫要能证明自己会红**：新写守卫时把修复摘掉跑一次，确认它变红且复现同一个错误。
   （踩过：探针因 CRLF/LF 不匹配静默失效，导致"验证的是空气"。）
4. **报错要能照做**：拒绝时说清"当前是什么、存档/输入是什么、该怎么办"，不静默降级。
5. **新增能力要有守卫**，且守卫写在"为什么这条可信"可被后来人定位的地方。
6. **改路径 / 写口 / 输出格式时，连带查"谁在断言它"**——包括不在 pytest 里的脚本与文档。
   （踩过：生成改道草稿区后，`scripts/worldgen_smoke.py` 仍断言产物出现在 `/api/catalog`
   且清理只删已发布区——前者会**假红**，后者会把冒烟垃圾留在 `_drafts/` 里等着被
   `git add -A` 提交；`scripts/replay.py` 则**直接崩**，因为它裸遍历 `world-packs/`。
   全量 pytest 当时是绿的，它盖不到这两条链。现已用
   `tests/test_catalog.py::test_world_packs_enumerators_all_discriminate` 把
   "谁遍历了 `world-packs/`、靠什么区分目录与卡"登记在案。）
7. **守卫不许被"别处的同一字符串"满足**——断言要限定到**发生位置**，不是"文件里出现过"。
   本仓库为此连踩五次，形状完全一样：① 判据被**注释**满足；② `say(e.message, true)`
   被**别的 catch 块**满足；③ `method: 'DELETE'` 被 `del` **辅助函数的定义**满足；
   ④ `... and ... or True`（`or True` 让它恒真）；⑤ `pack_digest(X) == pack_digest(X)`
   （同一路径当然等于自己）。
   对策：① `ast.unparse` 剥注释；② 用 `_function_body()` 限定到目标函数；
   ③ 检查**调用点**；④⑤ **写断言时先问它有没有可能不成立**。
   五次都是靠变异验证或事后复查才发现的——**新写守卫时先把它改坏一遍**。
8. **冒烟指令的歧义会被记成产品缺陷**。真机冒烟要**指名道姓**（点名 id 与字段），
   否则测的是"模型怎么理解你的模糊话"。反面也是收获：N6 第一轮用模糊指令时，
   模型**拒绝猜**并反问——那是设计意图，不是缺陷。
