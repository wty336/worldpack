## 3. 明确不做（三份文档合并去重）

**不做 DSH 插件 / TS 重写**——宿主明确禁止插件拥有回合循环，而本项目的护城河
（静态前缀冻结、审计不变量、Judge 门禁）都要求自己掌控它。完整论证见
`plan-dsh-tavern-parity.md` §3.1，含宿主侧硬证据。

**不做 ST 运行时兼容**（只做内容导入）——脚本沙箱、MVU、正则美化、预设、小手机。
实证：参考实现自己的兼容度远低于其宣传，且其默认模式把全局装到真实父窗口上。
见 `plan-tavern-shaped-product.md` §9。

**借鉴清单里明确不借的**（`sillytavern-borrow.md` D 系列）：PNG 卡信封、sticky/cooldown
定时、加权随机、7 种插入位置、双宏引擎，以及三条"看似缺失实为架构优势"的。

**暂不做**：场景配图、小手机、多账号、云端、多平台安装器（EXE/APK）、i18n、主题系统。

## 4. 纪律（改代码时照着做）

1. **改完必须跑离线全量**（934 项）；前端改动还要跑 `node scripts/webui_smoke.mjs`。
2. **改了 `game_agent/webui/src/**` 必须 `npm run build`**——`dist/` 入库，忘了重建测试会红
   （`tests/test_webui_build.py` 用内容哈希判定，不依赖 mtime）。
3. **守卫要能证明自己会红**：新写守卫时把修复摘掉跑一次，确认它变红且复现同一个错误。
   （踩过：探针因 CRLF/LF 不匹配静默失效，导致"验证的是空气"。）
4. **报错要能照做**：拒绝时说清"当前是什么、存档/输入是什么、该怎么办"，不静默降级。
5. **新增能力要有守卫**，且守卫写在"为什么这条可信"可被后来人定位的地方。
