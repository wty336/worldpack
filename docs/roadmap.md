### 1.1 N2a 与 N6 的边界：按"面"切，不按"前端 / Agent"切

**为什么要专门写这一节**：N2（创作工作台）与 N6（创作者 Agent）看起来像两件会互相打架的事——
一个做界面，一个做对话式改卡。读 roadmap 的字面会得出"先做表单工作台、之后再加 Agent"，
**而那个顺序会白做一块**。真实关系在 `plan-tavern-shaped-product.md` §5.1 里已经画出来了：

```
工作台 1：卡片/包库（浏览、选、导入）
工作台 2：编辑器（左边对话、右边字段与校验报告）
```

**"左边对话"就是 N6，"右边字段与校验报告"就是 N2 的报告面——它们本来就是同一个屏幕的两半。**
是"N2 前端 / N6 Agent"这种按技术层拆的写法，把一件事读成了两件。

**会白做的那一块是"手写字段编辑器"**（表单改 NPC 卡 / 世界书）。理由有三条，任一条都够：

1. **§4.1 的整个论证就是"结构化 CRUD 交给 Agent 比表单好"**——同一份文档里既说"表单不合适"、
   又排一个表单工作台，自相矛盾；
2. **用户的原话是"与 Agent 对话…修改人物设定和世界书"**——对话式才是要的目标，表单不是；
3. **表单会和草稿抢同一份真值**。Agent 改完草稿之后，表单里显示的是它上一次读到的值；
   要么表单得跟着 agent 的工具调用实时刷新，要么两边不一致。这是纯粹的 UI 状态同步债，
   换不来任何能力。

**所以按"面"切**：

| 面 | 归谁 | 内容 |
| --- | --- | --- |
| 生成流程 | **N2a** | 贴素材 → SSE 进度 → 取消 → 校验报告（含修复轮报错原文） |
| 草稿生命周期 | **N2a** | 草稿列表 / 试玩 / 发布 / 删除（后端 E-7 已就绪） |
| 显示面 | **N2a** | 右栏**只读呈现**字段、计数、`digest`、校验结论与 diff |
| 编辑面 | **N6** | 对话 + 工具轨迹 → 改草稿 → `validate_pack` → 报错回灌 → 再校验 |
| 记账 | **N6 开工即做** | Agent 调用要带按包/按会话的归因轴，否则重演 G-6 串号 |

**顺序**：N2a → N6。反过来的话，Agent 改完草稿没有任何地方看 diff 与校验结论，等于闭着眼改。
先做 N2a 不会返工——生成流程与报告渲染**本来就是 Agent 的显示面**。

### 2.1 N1 执行记录（2026-10）：后台任务 + 进度 SSE

**交付**：`game_agent/jobs.py`（任务表 + 串行执行器）+ 5 个端点 + `tests/test_jobs.py`（22 项）
+ `scripts/worldgen_smoke.py`（真机 SSE 冒烟）。

**为什么不能照抄 `_turn_stream`**：那个流是"一个请求 = 一个回合"——秒级、单一消费者、
断了就断了。生成是**分钟级**任务，形状根本不同：

| | 回合流 | 生成任务 |
| --- | --- | --- |
| 消费者 | 一个 | 可能多个；**刷新页面后还要能接上** |
| 断线 | 回合照跑，没人再看 | **必须能重连并看到已发生的全部进度** |
| 结果 | `done` 帧带完整视图 | 是个目录 + 一份成本报告，要能**事后**取 |

于是三件具体的事：
1. **事件留档 + 回放**（`job.events` 是事实来源，订阅时先回放再续播）——
   分钟级任务里刷新页面是常态，不是边缘情况；
2. **多订阅者广播**，慢消费者**只丢自己**（有界队列 + 省略提示），不阻塞生产者、
   不影响留档；
3. **取消**，检查点在**块与块之间**——一次 LLM 调用中途没法安全打断，也不该打断
   （半截响应没有意义，而钱已经花了）。取消落成 `cancelled` 而**不是** `failed`
   （取消不是失败，这是排查时第一个要看的信息）。

**四条护栏**（都是"能被脚本调用"才需要的，CLI 不需要）：
- **拒收文件路径**：接口只收 `source_text`。若收 `sources: ["../../.env"]`，就是一个
  任意文件读取洞（`read_sources` 会老实读出来喂给模型）；CLI 收路径没问题，那是本机
  用户手敲的。
- **拒绝覆盖同名包**：`materialize` 会先清空 `npcs/`，同名写入等于静默毁掉一个已发布的包。
- **并发上限 1**：同时跑两个生成只会两边都慢、费用翻倍且难以归因；排队是显式的
  （`status="queued"`），不是静默等待。
- **取消排队中的任务不发车**（否则白烧一次生成）。

**一个实测发现值得记住**：`TestClient` **会缓冲整个 SSE 响应体**——用它测"首末到达
间隔"恒为 0，那是客户端在缓冲，不是服务端。这一点是绕过 HTTP 直接消费 `_job_stream`
确认的（同一段代码，实测首末间隔 0.297s，与合成的 50ms×6 完全吻合）。
所以增量性守卫放在**生成器层**（`test_job_stream_yields_incrementally`，合成慢任务、
确定性），并额外留了一条 `test_testclient_buffers_sse_...` 当路牌——否则后来人会加一条
HTTP 层断言、得到假红，然后去改本来正确的服务端代码。
**已用变异验证**：把 `_job_stream` 改成"先睡到任务结束再发"，该守卫立刻变红。

**验证**：离线 **959 项全绿**；真机 SSE 冒烟 12 项全通过 + 1 项**如实报"不可判"**
（离线生成仅 0.09s，HTTP 链路增量性测不出——按 `test_qa_gate.py` 的纪律
"全部被跳过 ≠ 通过"，不可判就报不可判，不冒充通过）；冒烟自清理产物。

**遗留限制（已在 §2.2 解除）**：接口当时**拒绝覆盖同名包**（`materialize` 先清空
`npcs/`，同名写入等于静默毁掉线上包）。代价是"改一版再生成"只能不停换名字，
`world-packs/` 里会堆出 `foo` / `foo2` / `foo_new2`。

### 2.3 N2a 执行记录（2026-10）：创作工作台的共享外壳

**交付**：`webui/src/views/StudioView.vue`（工作台）+ `composables/useJobStream.js`
（进度流）+ `api/client.js` 8 个端点 + `LibraryView` 入口 + `App.vue` 三视图路由
+ `styles.css`；守卫 **+4**（含一条跨层契约）；真机冒烟 **18 → 36 项**。

**边界见 §1.1**：这一屏只做生成 → 进度 → 报告 → 试玩 → 发布，**不含手写字段编辑器**。
这条决定落成了一条**可执行断言**——冒烟直接断言"右栏输入框数量 = 0"。
设计决定写在文档里会被后人改掉，写成断言才会拦下来。

#### 三条设计判断

1. **"离线试跑"默认勾上**。真实生成一次约 ¥0.1–0.3，作者第一次点进来多半只是想看
   这条链通不通——**默认值就是产品决策**，默认让人花钱是错的默认值。取消勾选时有一句
   醒目的成本提示。这一条在**浏览器里**做过变异验证：把默认值改成 `false`，
   冒烟立刻 35/36。
2. **进度流的断线语义与回合流**相反**，两者结论不可互搬**：

   | | 回合流（POST） | 任务进度流（GET） |
   | --- | --- | --- |
   | 断线重连 | **会把回合重跑一遍**（重复扣费/落盘）→ 禁止 | 只是重新订阅，不重跑任何东西 |
   | 重连后收到 | 新的一回合 | 服务端**先回放全部历史**再续播 |

   所以这里仍然不用 `EventSource`（它的自动重连是无状态的，会让每次重连重收一遍历史），
   而是**有上限的显式重连**；且重连时**从空列表重建**日志——因为服务端总会回放完整历史，
   "重复行"这个问题在结构上就不存在，**不需要去重代码**。
3. **修复轮的报错原文来自 N1 的事件留档**（`repair` 事件），刷新页面后仍能回放。
   这是"事件留档 + 回放"的第二次兑现（第一次是后台任务自身）。报告栏把
   `stages / repairs / corpus_written / summary / cost` 一起呈现。

#### 三次假绿，同一个形状（本次最值得记的教训）

写这批守卫时**连续三次**写出"看起来在守、其实什么都没守"的断言，形状完全一样：
**把"某段代码存在"断言成"这个字符串在文件里出现过"**，于是被别处的同一字符串满足。

| # | 断言写法 | 被什么满足 | 改成 |
| --- | --- | --- | --- |
| ① | 源码里必须有某判据 | **注释** | `ast.unparse` 剥掉注释再查（§2.2 已记） |
| ② | `say(e.message, true)` 在文件里 | **别的 catch 块**也有这行 | 限定到 `publish()` 函数体内 |
| ③ | `method: 'DELETE'` 在文件里 | `del` **辅助函数的定义** | 检查 `deleteDraft` 的**调用点**用什么 |

前两次都是"改了被测代码、守卫照样绿"（用变异才发现）。已升格为 §4 纪律 7：
**断言要限定到"发生位置"，不是"文件里出现过"。** 配套加了 `tests/test_web_frontend.py`
的 `_function_body()` 助手。

#### 另一个洞：桩会同意我关于后端的假设

浏览器冒烟用**桩后端**（不花钱、可重复），代价是它由我手写——**我把响应键记错，
桩就照着我错的样子实现，冒烟照样全绿，而真机上是一片空白**。
补了 `test_workbench_payloads_carry_the_fields_the_view_reads`：用**真** app 跑一次
离线生成，逐个断言前端读的键真的存在（`job_id` / `cost` / `result.repairs` /
进度事件的 `stage,message` / 草稿项的 12 个键 / 开局的 `draft` 标记）。
**已变异验证**：把快照里的 `cost` 改名 → 立刻红。

## 4. 纪律（改代码时照着做）

1. **改完必须跑离线全量**（980 项）；前端改动还要跑 `node scripts/webui_smoke.mjs`。
2. **改了 `game_agent/webui/src/**` 必须 `npm run build`**——`dist/` 入库，忘了重建测试会红
   （`tests/test_webui_build.py` 用内容哈希判定，不依赖 mtime）。
3. **守卫要能证明自己会红**：新写守卫时把修复摘掉跑一次，确认它变红且复现同一个错误。
   （踩过：探针因 CRLF/LF 不匹配静默失效，导致"验证的是空气"。）
4. **报错要能照做**：拒绝时说清"当前是什么、存档/输入是什么、该怎么办"，不静默降级。
5. **新增能力要有守卫**，且守卫写在"为什么这条可信"可被后来人定位的地方。
6. **改路径 / 写口 / 输出格式时，连带查"谁在断言它"**——包括不在 pytest 里的脚本与文档。
   （踩过：生成改道草稿区后，`scripts/worldgen_smoke.py` 仍断言产物出现在 `/api/catalog`
   且清理只删已发布区——前者会**假红**，后者会把冒烟垃圾留在 `_drafts/` 里等着被
   `git add -A` 提交；`scripts/replay.py` 则**直接崩**，因为它裸遍历 `world-packs/`。
   全量 pytest 当时是绿的，它盖不到这两条链。现已用
   `tests/test_catalog.py::test_world_packs_enumerators_all_discriminate` 把
   "谁遍历了 `world-packs/`、靠什么区分目录与卡"登记在案。）
7. **守卫不许被"别处的同一字符串"满足**——断言要限定到**发生位置**，不是"文件里出现过"。
   本仓库为此连踩三次，形状完全一样：① 判据被**注释**满足；② `say(e.message, true)`
   被**别的 catch 块**满足；③ `method: 'DELETE'` 被 `del` **辅助函数的定义**满足。
   对策：① `ast.unparse` 剥注释；② 用 `_function_body()` 限定到目标函数；
   ③ 检查**调用点**。三次都是靠变异验证才发现的——**新写守卫时先把它改坏一遍**。
