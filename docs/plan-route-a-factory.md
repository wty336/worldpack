## 1. 背景与命题

### 1.1 为什么换掉"每模块手写生成器"

`plan-phase1-data.md` §4 的数据构造路线有两个结构性问题（2026-09-12 评审确认）：

1. **模板味**：纯程序化拼接的文本干净、结构单调，模型在其上训练后遇到真实作者的"脏文本"
   会退化（`plan-phase1-data.md` §8 已有此风险条目，但程序合成占主干 60% 的配比使风险落不了地）；
2. **text-first 标签循环**：若改用 LLM 生成文本再让 LLM 从文本反推标签（最常见的"LLM 造数据"
   做法），教师漏抽/误判的内容会变成"标准答案里的空洞"——**学生把教师的盲区一并学走**，
   且没有任何手段检测这种污染。

### 1.2 路线 A 的解法

**场景卡驱动（scenario-card-driven）**：程序先以结构化 JSON 定义"这沓文本里存在哪些事实、
哪里有错、错在哪"（= 标准答案），LLM 只负责把底稿**演绎**成自然文本。标签永远取自底稿，
**绝不读文本反推**。

LLM 在工厂中恰好三个角色，权限分明：

| 角色 | 职责 | 权限边界 |
| --- | --- | --- |
| **演绎器**（generator） | 场景卡 → 自然文本（回合内容/叙事/历史） | 只写表面形态；不得增删底稿事实（程序校验） |
| **标注器**（labeler） | 真实轨迹切片 → 标签 | **受限**：仅用于无场景卡可用的真实切片；上岗前须在合成切片上与程序标签对拍达标（§5） |
| **评委**（judge） | ① 拒绝采样选优 ② rubric 轨道评分 ③ 数据质检 | 每次上岗带已知缺陷探针校准；探针不合格当批作废（§7.3） |

### 1.3 范围

统一框架覆盖 Phase 1 侧信道（extract/judge/compress）与 Phase 2 主回合（预留接口，§10.4）；
**第一批落地 = Phase 1 三模块**，与 `plan-phase1-data.md` §1 决策表一致（dedup 不训、
reflect 数据照造但不进第一批训练）——**注：其中 extract 行经本文档决策 15 修订**
（先提示词收紧、复测再定量，见 §12.A 决策 15）。

## 2. 总体架构

```
                ┌─────────────────────────────────────────────┐
                │            场景卡生成器（纯程序）              │
                │  seed 隔离：train / dev / eval 三个种子空间    │
                └──────────────┬──────────────────────────────┘
                               │ ScenarioCard（JSON，即标签）
                ┌──────────────▼──────────────┐
                │   演绎器（LLM，temp 0.8~1.0） │  ← 语体/长度/脏度指令
                └──────────────┬──────────────┘
                               │ 自然文本
                ┌──────────────▼──────────────┐
                │  程序校验（底稿要素在位检查）   │  缺要素 → 重演一次 → 丢弃
                └──────────────┬──────────────┘
                               │
        ┌──────────────────────┼────────────────────────┐
        │                      │                        │
┌───────▼───────┐    ┌─────────▼─────────┐    ┌─────────▼─────────┐
│ 窄格式样本直接成对 │    │ 开放输出：候选 n=4    │    │ 质检员（LLM）抽检    │
│ (extract/judge) │    │ → 评委选优(compress) │    │ 自然度，滤模板味     │
└───────┬───────┘    └─────────┬─────────┘    └─────────┬─────────┘
        └──────────────────────┼────────────────────────┘
                               ▼
                   数据集（train）/ 评测集（dev, eval）
                               │
              ┌────────────────┴────────────────┐
              ▼ 轨道 1：规则评测（硬门槛）         ▼ 轨道 2：rubric 评测（质量结论）
```

真实轨迹切片走旁路：文本已存在 → 标注器（§5）→ 同样的质量门 → 入库（占比 ≤30%，继承原纪律）。

## 3. 场景卡（ScenarioCard）设计

### 3.1 设计要点

- **卡即标签**：extract 标签 = `card.facts`；judge 标签 = `card.corruptions`；compress 保全点 =
  `card.preserve_points`。任何模块的标签都不接触生成的文本。
- **轴值来自配额矩阵**：`axes` 字段的取值空间与 `plan-phase1-data.md` §4.4 轴覆盖矩阵一致
  （题材/语体/实体/数值系统/关系动力/违规形态/结构规模/输入形态），生成器按配额抽轴，
  **每轴至少一个取值只进评测集**的纪律改为"该取值只出现在 eval 种子空间"（§8 保证）。
- **可程序化校验**：`facts` 与 `preserve_points` 中的关键专名/数字以结构化字段登记，
  演绎后用字符串/正则程序校验"要素在位"，不依赖 LLM 自查。
- **材料侧也是标签的一部分**（本次补）：judge 的标签不只声明"哪里有错"，还须声明"材料里
  **有什么**"——`in_material` 标记 + `material` 装配指令（§3.2），否则错处无从对照。
  这条缺口原稿未覆盖：材料在 `judge.py` 里是 `ContextBuilder.status_text(...)` 的产物，
  没有生成者就无法造 judge 样本。

### 3.2 Schema（字段契约）

```yaml
card_id: sc-{seed}-{seq}
seed: 20260912            # 所属种子空间：train/dev/eval 三段隔离（§8）
module: extract           # extract | judge | compress | reflect
pack: world-packs/<pack>  # judge/compress 必填：材料由真实世界包物化（角色卡/属性 schema 来源）
axes:
  genre: 古代武侠          # 题材
  style: 口语叙事          # 语体
  entity_forms: [人名, 物品, 组织]
  stat_system: 银两        # 数值系统
  relation: 师门           # 关系动力
  scale: { nodes: 6, npcs: 2 }
  input_form: 首压          # compress 专用：首压 / 增量合并 / 长输入20K / 脏输入
facts:                     # extract 标签（程序拥有）；judge/compress 的事实底稿
  # anchors = 演绎后程序校验的专名；in_material = 该事实是否物化进「材料」（缺省 true）
  # confab 的断言事实标 false → 不写入 state.player_facts → 材料「关键事实」区为空
  #（这就是 plan-phase1-data.md §4.2.2「材料真值来源：facts 留空」的精确落点）
  - { type: 物品与装备, importance: 8, text: "玩家的剑名为「听雨」",
      anchors: ["听雨"], in_material: true }
  - { type: 债务与人情, importance: 6, text: "玩家欠老樵夫柴钱五十两，约定中秋前归还",
      anchors: ["五十两", "中秋"], in_material: true }
events: [ ... ]            # 事件序列（压缩/叙事文本的情节骨架）
existing: []               # extract 专用：已有事实 → 生产模板 `已有事实：{existing}` 段
                           #   （facts 为空 = 该回合无新事实 = 标签「无」；考去重纪律，§4.2.1）
old_summary: ""            # compress 专用：旧摘要 → 生产模板 `<旧摘要>` 段；首压为空串
corruptions:               # judge 标签（程序拥有）；extract/compress 为空
  - { category: setting,   # setting | confab | ooc
      target_fact: 0,
      method: 近义改写,      # 近义改写 | 指代漂移 | 时间线错位 | 实体合并
      detail: "剑名「听雨」演绎为「听风」",
      expect: "问题类型：设定矛盾" }
preserve_points:           # compress 必保全要点（程序规则可抽）
  - { text: "剑名听雨", anchors: ["听雨"] }
  - { text: "五十两债务与中秋期限", anchors: ["五十两", "中秋"] }
material:                  # judge 专用：材料装配指令（§4.1 材料装配器）
  day: 12
  scene: 上海·申报馆后门
  present: [station_chief] # confab 必须非空（说话人角色卡必进材料）
  # 好感档位决定**拦截通路数**：中性/亲近档（如 45）→ T1 纯缺席（只留"材料里没有"一条通路）；
  # 低好感档（如 8）→ T2 语气冲突（材料给出与承诺口气相悖的线索）。**45 是 T1，不是 T2。**
  affections: {station_chief: 45}
  facts: null              # 物化进「关键事实」区的**下标**：null=缺省取 facts[in_material=true]；[]=显式一条不写
  memories: {}             # 可选：{npc_id: [事实, ...]} → state.npc_memories
  recent: ""               # 最近 2 条「真实玩家发言」——**字符串**（与 context.py 的
                           #   status_text(recent: str = "") 同形；不是 list）
history_spec:              # 演绎规模指令
  turns: 8
  target_tokens: 3000      # 长输入档 = 20000 级
  noise: 日常寒暄           # 掺入的无关内容（负例素材）
```

完整示例共三张（A.1 extract 武侠卡 / A.2 judge·setting 民国谍战卡 / **A.3 judge·confab 民国谍战卡**）
见附录 A。

### 3.3 配额与质量门

- 生成器按 `plan-phase1-data.md` §4.4 矩阵出卡，**每格 ≥N 未达标不出库**（继承）；
- 每张卡出库前过 schema 校验（pydantic）：anchors 非空、`expect` 与 corpus 的
  `category/expected` 语义对齐（继承 `plan-phase1-data.md` §8"判官标签与门禁打架"对策）；
- **`corruptions` 与 `facts` 的对应规则**（本次补：原稿此处只写"`target_fact` 必须指向存在的
  facts 下标"，与 `plan-phase1-data.md` §4.2.2 的"`facts` 留空"直接冲突，confab 无处安放）：
  - `target_fact` 必须指向存在的 `facts` 下标；
  - `category: setting` → 所指事实必须 `in_material: true`（矛盾必须建立在**材料已知**的事实
    之上，否则判官会改走"缺席"通路 → 家族串味，跨包不可比）；
  - `category: confab` → 所指事实必须 `in_material: false`（该断言**不在材料里**，构成"纯缺席"）；
  - `category: ooc` → `target_fact` 可为 `null`（OOC 从物化后的角色卡 `boundaries`/`speech_style`
    出发改写，不依赖某条事实）；
  - `category: confab` 的卡，其 `facts` **全部**标 `in_material: false`（材料「关键事实」区为空，
    落实 `plan-phase1-data.md` §4.2.2 的"facts 留空"）；确需背景事实的变体须逐条显式标记并通过泄漏检查（§4.1 校验③）。
- **单通路纪律**（踩坑 #17 的推广）：每张 judge 卡**恰好 1 条** corruption——这一条管的是
  **注入错误数**；而**拦截通路数由材料侧决定**，两者不是一回事（A.3 即演示了同一张卡把好感
  降到低档就变成 T2 双通路）。故完整纪律为：每张卡 1 条 corruption，且**材料不得为同一切片
  引入第二条拦截通路**；**T2 变体作为独立切片出库**，不得与 T1 混在同一批报数。
  confab 另需过 §4.1 校验④（可推出性检查：断言不得由材料事实组合推出）。
  卡出厂跑 `scripts/card_hook_check.py --gate`（词面撞卡）+ 人读语义撞卡；
- 每条样本元数据 `{card_id, seed, module, axes, generator_version}`，数据集 sha256 入报告
  （继承 `plan-phase1-data.md` §6.4）。

## 4. 演绎器（Verbalizer）契约

| 项 | 约定 |
| --- | --- |
| 输入 | 场景卡 + 演绎指令（语体/长度/脏度/矛盾自然化方式） |
| 输出 | 自然文本：extract 用"回合内容"、judge 用"最新叙事"（含矛盾）、compress 用"新增历史" |
| 温度 | **0.8~1.0**（演绎要多样性；标注/评判类仍 temp=0，纪律不混） |
| 程序校验 | `facts.anchors` 全部在位（被 corruption 命中的 anchor 按 `detail` 反向校验）；缺失 → 重演 1 次 → 仍缺则丢弃该样本并计数。**confab 的 anchor 另需过 §4.1 校验③（不得出现在材料中）** |
| 截断 | `truncated=true` 丢弃（继承） |
| 矛盾自然化 | `corruptions.method` 决定演绎指令：近义改写=换词不换形；指代漂移=用"那把剑"等指代承载错误值；时间线错位=把事件挂到错误日期；实体合并=把两个 NPC 的事迹安到一人身上 |
| 预算 | 演绎输出上限按 `history_spec.target_tokens` ×1.2；批量并发，usage 记账落盘（继承 C2） |

**演绎器绝不做的事**：不得输出标签、不得修改 `facts`/`corruptions`、不得"顺手"在文本末尾
总结事实清单（防学生学到"文本自带答案"的伪相关）。

### 4.1 材料装配器（新增，补原稿缺口）

judge 的输入是**材料 + 最新叙事**，但原稿只规定了叙事侧由演绎器产出，**材料没有生成者**
（`judge.py` 的 `<材料>` 实为 `ContextBuilder.status_text(state, node)` 的产物）。本次补齐：

| 项 | 约定 |
| --- | --- |
| 输入 | 卡的 `pack` + `material`（§3.2） |
| 装配 | `GameState.from_pack(pack)` → 按 `material` 覆写 `day`/`scene`/`present_npcs`/`affections`，并把 `facts[in_material=true]` 与 `material.memories` 写入 `state.player_facts` / `state.npc_memories` → `ContextBuilder.from_pack(pack).status_text(state, None, recent=material.recent)`（同批上千张卡须缓存包加载，勿反复解析 YAML） |
| 硬纪律 | **必须复用生产组装器**，不得另写材料模板——与 `plan-phase1-data.md` §4.2.2 开头"输入模板必须逐字对齐生产调用"是同一条纪律，只是原稿漏在了材料侧 |
| 校验 ① | 材料非空，且 `material.present` 中的 NPC 角色卡确实落在材料里（confab"说话人在场"的前提） |
| 校验 ② | `in_material: true` 的 facts 的 anchors **必须在材料中在位** |
| 校验 ③ | **泄漏检查**：`in_material: false`（confab）的 anchors **不得出现在材料中** —— 泄漏即等于给判官开出第二条通路，退回踩坑 #17 的老坑；违反则该样本作废并计数 |
| 校验 ④ | **可推出性检查（人读，不可程序化，采样）**：confab 的断言**不得由材料已有事实组合推出**。`in_material: false` 只管"这条 fact 不入材料"，管不住"判官能从别的两条事实把它推出来"；材料里有「白鸮」又有「密码本在留声机里」时，叙事说"你答应把密码本交给白鸮"就可能被推出为合理 → 又变多通路 |

> **依赖**：judge 卡的材料必须由**真实世界包**物化，因此 `pack` 指向的包不存在时，judge 卡
> 只能先出 schema、出不了材料。G1（民国谍战）/G2 泛化包落地前，judge 模块走不到 M2 的完成态
> —— 这与 §10.3"G1/G2 素材可由工厂 eval 种子空间产出"是同一件事的两端。

## 5. 标注器（Labeler）：受限的 text-first

唯一允许"读文本反推标签"的环节，仅服务于**真实轨迹切片**（无场景卡可用的存量资产）。
防循环论证的**三道闸**，外加一条**量级纪律**（第 4 条不是防循环的闸，是判据可判性的前提）：

1. **上岗考试**：标注器先在 ≥100 张合成卡切片上与程序标签对拍（extract 事实一致率、
   judge 判定一致率），**≥95% 才允许标注真实切片**；不达标则该模块的真实切片放弃补标，
   退回纯合成；
2. **temp=0 + 3 次多数票**（继承 2026-09-12 非确定性协议）；
3. **占比上限**：真实切片 ≤ 训练集 30%（继承原计划 20~30% 档），且按包留出后仅 3 包可用；
4. **错标率与判据同阶，必须分量级**（本次补）：上岗线 95% 意味着真实切片自带约 5% 错标，
   而这批占训练集 ≤30%；`plan-phase1-data.md` §6.2 的判据却是"≥ flash − 5pp"——**噪声与判据同阶**。故：
   - **分模块设线**：`judge` 真实切片要求 **≥97%**（把违规判成"通过" = 教模型放过违规，
     不可容忍）、`extract` **≥95%**（漏抽 = 教模型少抽，可容忍度高）；
   - 上岗考试**错标率与一致率同时报**——只报一致率会把"全判通过"的退化解报成高分；
   - 某模块错标率若高于判据余量（>3%），其真实切片配比从 30% 下调，缺口由合成档补。

## 6. 开放输出的训练目标：教师示范 + 拒绝采样

compress（及 Phase 2 的叙事）没有唯一正确答案，直接抄教师单次采样会把天花板锁在
"教师平均水平"。路线 A 用**拒绝采样**抬天花板：

| 档 | 做法 | 成本（估算，§10.2） | 适用 |
| --- | --- | --- | --- |
| 关 | n=1，教师单次示范即训练目标 | +¥0 | 预算卡死时 |
| **默认** | **仅长输入档（20K）开 n=4** | +¥12 | 实测最弱档（保全率 0.27） |
| 全量 | compress 全部 300 对开 n=4 | +¥31 | 预算宽裕时 |

选优协议：

1. 同一输入生成 4 个候选（temp=0.8，候选间求异）；
2. **程序先杀（强度取决于数据源，本次补）**：
   - **有卡档**（合成；含 20K 长输入档的合成部分）：规则全开——虚构（对照卡的事实底稿）、
     缺必保全点（对照 `preserve_points`）、超长，均可程序淘汰，**省评委输入**；
   - **无卡档**（真实轨迹切片，经 §5 标注器补标）：只有长度/截断/契约三条可程序判；
     **虚构与保全必须交 rubric 评委**，此处评委输入无法省。
   因此默认档（§12 决策 12）的 n=4 **只对有卡档开放**；无卡档一律 n=1；
3. 幸存候选交 rubric 评委按 §7.2 量规打分，取最高分为训练目标；并列取较短者；
4. 若 4 候选全被程序淘汰 → 该样本标记 `hard`，重生成一次，仍全灭则弃样并计数
   （`hard` 率 >10% 时停下查演绎器，不硬造数据）。

## 7. 双轨评测

### 7.1 分工铁律

- **轨道 1（规则）= 硬门槛**：extract 召回、judge 拦截/误报、dedup 冻结护栏、compress 规则
  保全率、契约合规率——全部继承 `plan-phase1-data.md` §6.2/§6.3，决策门只看轨道 1；
- **轨道 2（rubric）= 质量结论**：回答"摘要好不好/（Phase 2）叙事好不好"这类规则失效的问题。
  rubric 轨道**不单独否决**训练结论，但其探针校准记录必须随报告出具；轨道 2 与轨道 1 结论
  冲突时，先怀疑评委（复校探针），再怀疑规则代理（人工抽检），最后才怀疑模型。

### 7.2 rubric 量规（compress 四维，打分制）

每维 0~2 分，锚点写死（完整表见附录 B）：

| 维度 | 测什么 | 与规则轨道的关系 |
| --- | --- | --- |
| 保真 | 摘要是否引入源材料不存在的内容（语义层失真，规则查不出的改述歪曲） | 互补：规则管"要点在不在"，rubric 管"多出来的坏东西" |
| 简洁 | 是否混入寒暄/流水账/重复信息 | 互补负例轴 |
| 结构 | 五类信息（关系/承诺/事件/目标/失败）是否组织清晰可检索 | 纯 rubric |
| 流畅 | 作为给后续回合的上下文是否可读、无断裂 | 纯 rubric |

**成对比较**（偏好率，用于"训练后 vs flash"结论）：同一输入两份输出匿名、随机左右序，
评委只回答"哪边更好/平手"，每对交换位置复评一次，三次重复（temp=0）取多数。
打分制用于绝对门槛（如保真 <2 即不合格样本检出）。

### 7.3 评委校准协议（每批评测强制执行）

1. **探针掺入 ≥10%**：程序改坏的样本（删要点/注入虚构/打乱结构）混入评测队列。
   检出口径分模式：打分制 = 探针的对应维度分必须落入 0 分档；成对比较 = 探针（坏）与
   干净样本配对时必须被判负。探针检出率 <90% → **当批成绩全部作废**，修评委提示词后整批重评。
   **坏法分级（2026-09-13 补，spec §11 风险表处方的落地）**：§7.2 明写 `保真` 只管"多出来的坏东西"、
   "**规则管要点在不在**"——故考**覆盖**的「删要点」不该由 rubric 判（实测：判官对"整条要点被删但兄弟条目
   仍提到该事"给 1 分是**合理**的，而探针却期望 0 → 必然漏检）。分级为：**显性级**（缺陷落在被度量的维度上：
   注入虚构→保真、结构崩坏→结构）计入门；**覆盖级**（删要点）只作诊断并留档。另三条配套：
   ① 坏法必须**可离线证明**（删要点要删到 anchor 与要点 4 字串全无；打乱结构要剥除骨架，否则摘要是分节
   要点表的材料上"仅打乱句子"仍可能被读成结构尚可）；② 探针**构造失败 = 无效 ≠ 漏检**（剔出统计并留痕，
   无显性探针时检出率记"未知"、批无效）；③ **分层抽样**保证每批 ≥1 个显性探针（逐位随机抽有概率整批落覆盖级
   = 抽样运气废掉整批）；
2. 位置交换 × 3 重复，报"按 run 计 + 逐例稳定率"（继承 2026-09-12 协议）；
3. **人类子样本**：每批抽 ≥10 对由人复核，报告评委-人类一致率；一致率 <80% 时
   结论降级为"仅供参考"并重写量规锚点；
4. 评委模型与温度写入报告（`judge_model`, `prompt_version`，继承 `plan-phase1-data.md` §6.4 schema 扩展字段）。

### 7.4 数据质检员（第三处评委用法）

合成样本入库前抽检 20%：评委只评"自然度/模板味"（0~2），<1 的样本剔除并重造。
这是防"演绎器退化回模板"的常驻关卡，不是一次性检查。

### 7.5 标签自检（2026-09-13 补，第五处评委用法）

**为什么补**：验收暴露的两个缺陷是**同一形态**——**不报错、但产出坏标签**：
① `card_id` 跨模块重复 → 质检剔除按 id 连坐（实剔 3 报 1）；
⑦ 名字池不分语义槽 → `preserve_points` 声称的内容在材料里根本不成立（「装备名为**旧书店**」）。
一天内让决策 14 的 eval 例外条款触发了**两次**。程序侧只查得出"anchor 在不在"（**字面**），
查不出"这条事实在文本里是否**被当成本身所述的那种东西**成立"——而那正是演绎器会悄悄改掉的地方。

**口径**：入库前抽检 20%，一次调用校验"一组标签 ↔ 一段文本"：
· extract 送 `labels`、compress 送 `preserve_points`；
· **judge 送「问题类型 + 矛盾依据 + 说话人角色卡 + 材料 + 叙事」**（`JUDGE_LABEL_SYSTEM`，判"这段叙事是否**真的**呈现出该问题类型"）。
  **更正（2026-09-13 发现⑧）**：先前写的"judge 标签由 anchors 程序保证 → 跳过"**只对 setting 成立**——
  `ooc` 在工厂路径上**没有任何校验**：`_corruption_swap` 对 ooc 返回 `hit_idx=None`、无引用值，
  锚点校验退化成"事实 anchors 在位"（与 OOC 无关），`hook_gate` 也只查 confab。
  旁证：项目另一条路径（`build_judge_corpus.py`）的 ooc 是**手工卡面锚定**的（逐条引用 boundaries/forbidden + 依据），
  说明"ooc 需要锚定"本是已知结论，是工厂这条路径少了它。故 judge 三类**都**进自检。
· 判定：`{成立: bool, 不成立项: [...]}`；**空响应/JSON 解析失败 = 未判定**（"空 = 未知 ≠ 通过"，
不得当通过）；不成立的样本**剔除**并把清单留档 `label-check-{layer}.json`。
· 指纹独立记（`label_check_version()` = 两条自检提示词的 sha16），**不并入** `prompt_version()`——
否则新增校验器会把已记录的 X 校准指纹牵连作废。

**双向验证（2026-09-13 实测）**：阳性对照 = ⑦ 修复前批的两张已知坏卡，校验器**精确抓到**
`「玩家的装备名为「旧书店」」` 与 `「玩家欠密码本五十两，约定中秋前归还」`，同卡的正常标签不误报（2/2）；
阴性对照 = ⑦ 修复后批抽检 **33 条 → 0 违规**（不误报）。

## 8. 一厂两库：train / dev / eval 三层划分

| 层 | 种子空间 | 用途 | 纪律 |
| --- | --- | --- | --- |
| train | 10,000~19,999 | 训练 | 与 eval 前缀级指纹去重（继承 `plan-phase1-data.md` §3.3） |
| dev | 20,000~29,999 | 早停 / checkpoint 选择 / 调参 | **可再生**：同范围换 seed 随时重造，不冻结 |
| eval | 30,000~39,999 | 决策门 | **冻结**：git tag + sha256；**每个决策门只打开一次，打开次数记入报告** |

- "每轴至少一个取值只出现在评测集"实现为：该轴值在生成器中只对 eval 种子空间开放
  （如 G1 民国谍战、G2 书信体组合）；
- 解决 2026-09-12 评审提出的「模型选择过程会污染冻结集」问题：模型选择全过程只见 dev，
  冻结集不会被决策过程污染；
- **留出轴的 dev 孪生**（本次补）：留出轴取值只对 eval 开放，会带来一个副作用——**早停只见
  dev，而 dev 里没有该轴值**，"dev 最优"与"eval 最优"之间没有桥，决策门 1 成了首次观测。
  故为每个留出轴配一个**同类不同取值**的 dev 轴值（eval = 民国谍战 → dev = 抗战谍战；
  eval = 书信体 → dev = 日记体），dev 取值**不得**与 eval 取值重合（§12 决策 19）；
- 既有 `eval-sets/`（dedup 123 对、extract **42 例 = 31 正 + 11 负**，2026-09-12 极性修正后；
  sha256 见 `eval-sets/digests.json`）继续作为 eval 层一部分，其既有指纹与新工厂样本做跨库去重。

## 11. 风险与对策（在 `plan-phase1-data.md` §8 基础上新增）

| 风险 | 表现 | 对策 |
| --- | --- | --- |
| 演绎偏离底稿 | 漏要素/改事实 → 标签与文本脱节 | 程序 anchors 校验（§4）；重演一次仍缺即弃；偏离率入报告 |
| 评委自族偏袒 | 偏好与自己同源的文本风格 | 成对比较匿名 + 位置交换；评委与教师可用不同模型档（如评委用 flash、候选含基座采样） |
| 探针失效 | 改坏样本"坏得不明显"，评委检不出 ≠ 评委不靠谱 | 探针坏法分级（显性删要点 → 隐性改述歪曲），按级分别要求检出率 |
| 场景卡多样性不足 | 卡本身模板化 → 演绎再自然也窄 | 轴配额矩阵管卡（§3.3）+ 质检员管文本（§7.4）双重防线 |
| 成本超支 | 演绎重试/拒绝采样放大调用量 | 默认档即开关设计（§6）；usage 记账每批出账；超 ¥90 停批复盘 |
| 评委提示词漂移 | rubric 改了，历史分数不可比 | rubric 文本纳入 `prompt_version` 哈希口径 |
| **材料泄漏**（confab） | `in_material: false` 的事实被误物化进材料 → 判官多出"设定矛盾"通路，拦截率虚高、跨包不可比（= 踩坑 #17 复发） | 装配后强制跑泄漏检查（§4.1 校验③）；违反即作废样本并计数 |
| **dev 对留出轴全盲** | 留出轴值只对 eval 开放 → 早停只见 dev、而 dev 无该轴值 → "dev 最优"与"eval 最优"之间没有桥，决策门 1 是首次观测 | 为每个留出轴配**同类不同取值**的 dev 孪生轴值（§8 / §12 决策 19） |

```yaml
material:
  day: 12
  scene: 上海·申报馆后门
  present: [station_chief]             # confab 必须非空：说话人角色卡必进材料
  affections: {station_chief: 45}      # T1 档：中性好感 → 材料不提供语气线索，只留"缺席"一条通路
  # 省略 facts（= null）→ 缺省取 facts[in_material=true]；本卡全 false（§3.3 强制），
  # 故材料「关键事实」区自然为空 = 该承诺零信号。**不是漏了字段。**
  memories: {}                         # 若写记忆，也必须不含"密码本/白鸮"（§4.1 校验③泄漏检查）
  recent: "你在后门等了一刻钟，没等到人。"   # 检索相关性上下文（字符串，§4.1）；也不得提到密码本/白鸮
history_spec: { turns: 1, target_tokens: 600, noise: 街景白描 }
```

**卡面要点**：`in_material: false` 的那条事实，就是"**叙事要断言、材料要缺席**"的那一条；
`corruptions[0]` 的 `category: confab` 与 `target_fact: 0` 必须指向它（§3.3）。
`affections` 取中性档（45）使材料不提供语气线索，从而只留"缺席"这一条通路（T1）。
**要造 T2（语气冲突）只需把 `affections` 降到低好感档**（如 8），其余不动——两档同卡可出，
但评测必须分切片报（`plan-phase1-data.md` §6.2）。

## 附录 B · compress rubric 量规（打分制，每维 0~2）

| 维度 | 0 分（锚） | 1 分（锚） | 2 分（锚） |
| --- | --- | --- | --- |
| 保真 | 出现任一源材料不存在的事实/数字/人名 | 无虚构，但有关键改述失真（如条件/时态被弱化） | 全部内容可在源材料中找到出处 |
| 简洁 | 混入寒暄/流水账 ≥2 处 | 有个别冗余句，但不干扰检索 | 无一句可删 |
| 结构 | 五类信息混杂无法检索 | 有分节但归类有错 | 五类信息分节清晰、可定位 |
| 流畅 | 读作上下文会断裂（指代不明/时序混乱） | 基本可读，个别指代需回查 | 作为后续回合上下文可直接使用 |

探针坏法：① 删除 1 个必保全要点（考覆盖检出）；② 注入 1 条虚构数字（考保真）；
③ 打乱分节并混入 3 句寒暄（考简洁+结构）。每批每类 ≥3 条，总占比 ≥10%。
