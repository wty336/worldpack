**判定：按文档 §5.4 预期路径 → 进入 Phase 1（窄模块蒸馏），主回合去留留待 Phase 2 决策。**

| 决策门判据（§5.4） | 实测 | 判定 |

**一句话结论**：14B 零样本的**上限高**（两包通关、dedup 满分、judge 误报 0%、文风成立），

窄模块已接近可用，主回合协议遵从是 Phase 2 蒸馏的首要目标，事实提取是 Phase 1 的
重点模块。

## 3. A 轴：协议（重点章节）

### 3.1 三类数据源

1. **生产形态 smoke 对照**（阶段 3/4，同命令同轮数）：flash 三包全过零协议失败；
   14B xianxia/urban 通关、ancient 2 次 run 均熔断、长局回合 0 熔断。
2. **ICR v1**（83 前缀，无状态栏）：14B 一次通过 42.4%、熔断 12%；flash 13.4%。
3. **ICR v2**（60 前缀，终局状态栏 + 污染剔除）：14B 36.4%、熔断 27%；flash 8.6%。

### 3.2 reasoning_content bias（本阶段最重要方法论发现）

- **现象**：flash 生产轨迹零协议失败，但 ICR 重放下一次通过率仅 8.6-13.4%、还出现
  2 个熔断——且"带状态栏"（v2）比"无状态栏"（v1）更差，推翻了"无状态栏形态 artifact"假设。
- **根因**：DeepSeek V4 在携带 tools 时要求回传 `reasoning_content`（llm.py 注释明示），
  flash 的协议输出 = 思维链 + 工具调用的组合；**存档不保留 reasoning_content**（§2.4 已知），
  ICR 重放输入缺失它 → flash 协议遵从崩溃。Qwen AWQ 无 thinking 输出、不依赖该字段 →
  **14B 的 ICR 数字不受此 bias 影响**（v1/v2 跨形态稳定在 36-42%）。
- **推论**：文档 §7.4 的 ICR 对拍设计在"teacher 是带思维链的模型"时对 teacher 不公平；
  Phase 2 盲评时同样注意（评的是无思考链的产物 vs 有思考链的产物——正好是本地化
  场景的真实形态，结论可用但需注明）。生产形态 A 轴以 smoke 对照为准。

### 3.3 14B 协议失败的两类模式（阶段 1/4 诊断）

1. 纯文本不调工具（finish_reason=stop，把选择列表写进正文，逼近 2048 上限）；
2. hermes `<tool_call>` 块 JSON 损坏 → vLLM 解析器静默丢弃 → 引擎判「无工具调用」。
两者都指向同一能力缺口：**零样本 14B 的协议格式遵从不稳定**——正是文档 §7.1 预判的
"SFT 最容易学会的东西"，Phase 2 蒸馏首要目标。

### 3.4 输入污染（v2 修正）

flash 时代的坏 JSON tool_calls 残迹会让 vLLM 模板解析历史消息时报 400
（DeepSeek 端点宽容）；memory-regression 300 轮长局 121 边界中 110 个被污染剔除。
**重放/训练输入必须按 §7.2 清洗黑名单过滤。**

## 4. B 轴：判定一致

| 模块 | flash | 14B | 达标？ |
| --- | --- | --- | --- |
| judge（三包对抗语料，rounds=3） | 拦截 100%、误报 0% | 拦截 83/89/94%（ancient setting 4/6 拖累）、误报 0% ×3 | ❌ 拦截差 6-17pp（−5pp 判据）；误报达标 |
| dedup（10 组近义对，temp=0） | **100%**（09-11 预算修复后重测；旧 40-50% = `DEDUP_MAX_TOKENS=50` 被思考吃光的预算 bug） | **100% 稳定** | ✅ 双方均满分（原记「大幅超标」不成立） |

- judge 的差距集中在一类（ancient setting 4/6）——小样本下 1 条即 16.7pp；
  Phase 1 judge 蒸馏优先补 setting 类（时间矛盾/身份矛盾/数值矛盾）。
- dedup 的 flash 数字（§retro 5.3）**不是能力退化**：2026-09-11 晚裸调实锤 `DEDUP_MAX_TOKENS=50`
  被思考模式吃光（`finish_reason=length` + content 空），引擎把空输出判为「不重复」→ 放行；
  与 reflect 空响应（§retro 8.2，`REFLECT_MAX_TOKENS=200`；放宽到 2000 后 flash 正常产出）**同根因**。
  影响：**对照线 40-50% 已作废**——2026-09-11 预算修复后重测，flash 为 **10/10 = 100%**，
  与 14B **持平**；14B 的 100% 本身不受影响（无思考模式）；
  flash 补标环节必须放大 max_tokens；引擎侧空响应升级重试已推广到 dedup/reflect/extract
  （commit `a058b34`，复盘 §10.4）；重测全过程见
  `reports/sidechannel-budget-retest-20260911.md`。

## 7. E 轴：资源经济

| 项 | 实测 | 对照 |
| --- | --- | --- |
| ICR 均时（短/中前缀 1-22K） | local 13.3-13.4s / flash 12.0-15.4s | 本地不慢于云端 |
| prefill 吞吐 | ~600 tok/s（低于 D.3 预估 3-8s/3万token） | 20K 前缀 TTFT 需 ~15-30s（chunked prefill 2048 批大小限制，可试 `--max-num-batched-tokens` 上调） |
| generation 吞吐 | 35-56 tok/s | D.3 预估区间内 |
| 显存 | 21.8/24GB（AWQ 4-bit + KV fp8 + 0.85 util） | 4090 单卡可行 |
| prefix cache hit | 87%（本地）/ 84-96%（flash 服务端） | 静态前缀稳定红利兑现 |
| flash 成本 | Phase 0 全期 ≈¥3（cache 红利） | 远低于预算 |

**可玩性初判**：短局（≤20K 前缀）观感可接受（回合 13-30s，流式边生成边显示）；
20K+ 前缀 TTFT 需调参或加深小窗档（compress_threshold 18K）。
