## 4. 为什么**不**再迭代第二轮（过拟合论证）

要让两侧同时达标，需要四处子句补丁，且每处都**由具体用例反推**：

1. 判定式重新锚定「关于**玩家**的」→ 修 `n_funds`；
2. "数字或数值"限定为"**构成上述类别的一部分**（欠款额、承诺期限、编号、装备参数）"→ 修 `n_funds` + `p2_ticket`；
3. dedup 子句改为"已有事实**不复述**，但**新增信息必须输出**"→ 修 `x_dedup`/`s_dedup`/`p2_dedup`；
4. "瞬时状态"只排除**纯动作与场面描写**，其中出现的具体物品/专名仍属事实 → 修 `t_arm`。

这是**在 42 例的尺子上做四点拟合**，而 extract 没有独立留出集（`eval-sets/MANIFEST.md` 的冻结集就是尺子本身）；
按项目纪律（"空 = 未知 ≠ 通过"、判据封板不得事后松动），**不把拟合结果当达标**。

| 问题 | 答复 | 依据 |

| 能否用提示词替代 extract 训练？ | **不能**（且不该按这个方向省训练量） | 14B 用了"为它定制的"新版提示词后仍是 **71/93 = 76.3%**，仍**低于 flash 用旧提示词的 89/93 = 95.7%**；且仍余 7 个 C 类 run、15 个 B 类 run |

| 训练数据该重点覆盖什么？ | 本轮实测暴露的**两个真实短板**（比提示词补丁更稳的产物）：①**"已有事实的新增信息"**（dedup ≠ 沉默）；②**"瞬时场面中的具体物品与参数"** | §3 的 6 个用例逐条可指名 |
| 提示词改动如何处理？ | **撤回**（`game_agent/memory.py` 复原为 `99668791ed5957fc` 版） | 对现役 flash 三项全退化；未达标物不得留在引擎里 |
