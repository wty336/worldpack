## 2. 设计要点（为什么这么造）

1. **dedup 必须有负例**。旧 `scripts/dedup_test.py` 的 10 组**全是正例**——一个"全部判重复"的
   模型同样能拿 10/10 = 100%。本集同时报告**拦截率（正例）**与**误拦率（负例）**，
   两者都要过线才算通过。
2. **历史 10 组原样保留**（`hist_01..hist_10`）：让新旧数字可衔接（含历史难例 `hist_10`
   「剑法平平 vs 武功剑法很一般」与 `edge_03` 主客颠倒）。
3. **`must_recall` 是"关键实体"而非全文**：判分按实体覆盖（同义表述容忍），对齐仓库既有的
   规则抽取风格（`phase1_probe.eval_compress` 的保全率）。
4. **`must_not_output` 承载去重纪律**：已有事实不得重复输出（5 条 dedup 型用例专测这个）。
5. **负例用 `expect_empty: true` 显式表达**（该回合无长期事实 → 应输出「无」→ `parse_facts` 得空列表），
   不靠"空 must_recall"隐式推断。
6. **跨题材是硬要求**：题材是"防窄化"的最小轴（见 `docs/plan-phase1-data.md` §4.4），
   后续版本会继续按轴补（如书信体、外国译名、信誉/声望数值系统）。

```bash
# 1) 改 scripts/build_eval_sets.py 里的种子（DEDUP_SEEDS / EXTRACT_CASES / 边界用例）
python scripts/build_eval_sets.py --digests    # 2) 重新渲染 + 刷新 eval-sets/digests.json
```

1. extract 在**未钉温度**时三跑为 92% / 92% / 79%（±13pp），同一用例可 3 条↔0 条地翻转

## 6. 出题纪律（2026-09-12 总结，两条反复犯的错）

首跑/扩域过程中我（出题人）反复犯同一类错，模型反而是对的 —— 记为硬规则：

1. **瞬时状态不是长期事实**：经费/粮票余额/零花钱/天气/临时位置 → **不要写进 `must_recall`**，
   模型输出「无」是正确答案（已犯于 `s_debt`、`n_funds`、`p2_ticket`）。
   **后续处置（2026-09-12）**：`p2_ticket` 已于 §7 改负例；`n_funds` 于决策 20 补齐改负例；
   `s_debt` 经复核属**部分漏抽**而非拒答，归类系笔误、保持正例 —— 详见 §9。
2. **带新信息的复述不是重复**：新承诺、新进展、状态更新（"小马说下月一定还"）都是**合法新事实** →
   应由 `must_not_output` 存**完整已有事实**来做去重纪律检查，**不要**指望模型什么都不输出
   （已犯于 `p1_dedup`、`p2_dedup`、`t_dedup`）。
3. 判分用的实体匹配是**字面**的：中文数字与阿拉伯数字（三百 vs 300）不通用 → 出题时统一数字写法
   （已犯于 `s_debt`、`n_funds`）。

> 这三条都靠"逐轮原始输出 + 判官/模型判词"才查出来 —— 因此 `extract_eval` 现要求**每条 run 自带
> `raw_output`**，翻转用例必须能回看现场，否则会把"我出题错"误读成"模型窄化"。

## 8. 版本与迁移策略（2026-09-12 定）

**问题**：尺子会变（扩域、修标签、改种子）。若"改一次、测一次"，钱会白花，历史数字也无法对账。

**三条规则**：

1. **加性扩展，不改既有条目**：新增用例另起 id，老条目文本不动。
   老数字因此**永久有效**，作为"v1 切片"保留；新数字按全量报，两者并排、不混用。
   （唯一例外：旧三包 confab 的 8 条词面撞卡条目待重造 —— 那三包的 confab 必须重测。）

2. **每次报告自证来源**（schema 见 `docs/plan-phase1-data.md` §6.4）：
   - `content_version`：语料内容版本（生成器写入 `judge_corpus.gen.yaml` 顶层；
     现值：三包 `v1-2026-09-07`、P1/P2 `v3-2026-09-12`）；
   - `case_set_digest`：**这一次实际跑到的用例 id 集**的散列（部分类别运行、增量扩语料时尤其重要）；
   - `endpoint`：部署指纹（权重 repo / 窗口 / 服务实现）；
   - `category_filter`：非空 = 部分运行，**不是门禁口径**。

3. **合并重测周期**：一处语料改动 → 攒齐所有改动 → 两侧各重测一次
   （flash 只跑变动族 ≈¥0.5~1.3，14B 免费整包）。**换尺子后不重测 = 假对比**（§3.5.6c 教训）。

**离线重切优先**：报告里逐轮 verdict 都在，所以像 confab 的 T1/T2 分切片这种事
（`scripts/tier_slice.py`）不需要重跑模型 —— 先问"能不能离线重切"，再决定要不要花钱重测。
