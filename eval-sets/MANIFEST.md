## 2. 设计要点（为什么这么造）

1. **dedup 必须有负例**。旧 `scripts/dedup_test.py` 的 10 组**全是正例**——一个"全部判重复"的
   模型同样能拿 10/10 = 100%。本集同时报告**拦截率（正例）**与**误拦率（负例）**，
   两者都要过线才算通过。
2. **历史 10 组原样保留**（`hist_01..hist_10`）：让新旧数字可衔接（含历史难例 `hist_10`
   「剑法平平 vs 武功剑法很一般」与 `edge_03` 主客颠倒）。
3. **`must_recall` 是"关键实体"而非全文**：判分按实体覆盖（同义表述容忍），对齐仓库既有的
   规则抽取风格（`phase1_probe.eval_compress` 的保全率）。
4. **`must_not_output` 承载去重纪律**：已有事实不得重复输出（5 条 dedup 型用例专测这个）。
5. **负例用 `expect_empty: true` 显式表达**（该回合无长期事实 → 应输出「无」→ `parse_facts` 得空列表），
   不靠"空 must_recall"隐式推断。
6. **跨题材是硬要求**：题材是"防窄化"的最小轴（见 `docs/plan-phase1-data.md` §4.4），
   后续版本会继续按轴补（如书信体、外国译名、信誉/声望数值系统）。

## 4. 修改流程（重要）

```bash
# 1) 改 scripts/build_eval_sets.py 里的种子（DEDUP_SEEDS / EXTRACT_CASES / 边界用例）
python scripts/build_eval_sets.py --digests    # 2) 重新渲染 + 刷新 eval-sets/digests.json
python -m pytest tests/test_eval_frozen.py -q  # 3) 守卫转绿
# 4) 同步更新本文件的"版本/日期/规模"与 §1 表格
```

- **禁止手改 `eval-sets/*.yaml`**：`--check` 与守卫测试都会失败（这是刻意的）。
- 每次改动 = 一次**显式解冻**：评审时 git diff 会同时显示数据变化与 digest 变化。

## 5. v1 基线（flash · 2026-09-12）

| 评测 | 命令 | 结果 | 稳定性 |
| --- | --- | --- | --- |
| dedup | `scripts/dedup_test.py` | 正例拦截 **64/65 = 98%** · 负例误拦 **0/58 = 0%** | 两跑 97% → 98%（1 例翻转）；稳定 miss 1 例（`xianxia_master-syn1`：师父姓陆 vs 师从陆姓镖师） |
| extract | `scripts/extract_eval.py --repeat 3 --temperature 0` | 召回 **65/72 = 90%**（按 run 计）· 去重违规 **0** · 负例 **18/18** · 综合 83/90 = 92% | **逐例稳定性 26/30（4 例翻转：`x_relation`/`s_debt`/`n_cover`/`n_dedup`）** |

**⚠️ 关键发现：评测噪声不可忽略** ——

1. extract 在**未钉温度**时三跑为 92% / 92% / 79%（±13pp），同一用例可 3 条↔0 条地翻转
   （`n_cover`）。故评测侧默认 `--temperature 0`；生产 `_extract_facts` 仍走供应商默认（**待产品决策**）。
2. 即便钉死温度，仍有 4/30 例在重复间翻转 → 非确定性**不全来自温度**（疑服务端路由/版本漂移，
   与 retro 记录的"flash 换代"同源）。
3. **协议要求**：所有评测 ≥3 次重复，报告"**按 run 计率** + **逐例稳定率**"两个指标；
   单跑数字不得进入结论（训练前后差异须大于噪声底噪 ≈ ±5~10pp 才可判有效）。
